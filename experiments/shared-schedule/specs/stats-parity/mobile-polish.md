# R9 移动设计打磨评估

2026-10-02 用户手机反馈“显示正常，但设计需要优化吧”。本文件是下一轮设计建议；本次仅检查现有页面并记录验收反馈，未修改界面源码，也未生成新的设计版本。

## 检查依据

检查 R9 微信原生首页、选手档案、排行榜截图，以及当前 Stats 本地选手页在 390×844 视窗下的真实界面与计算样式。网站对照页当时出现数据更新失败/重新更新状态，封面图未显示；不把这些状态误记为小程序的故障。截图中微信模拟器的显示缩放不用于推断字号；字号判断以 Stats 计算样式为依据。

选手页的品牌栏为 56px，更新状态下的赛事信息块为 83px，档案页签为 48px；档案封面从 y=254px 开始，姓名位于 y=354px。赛事状态及职责等次要信息为 11px，赛事中心副标为 10px，返回按钮文字为 12px；姓名约 33px、封面主体文字为 15px。由此应优先改善顶部信息密度和次要文字的可读性，保留现有姓名与荣誉的视觉重点。上述高度是该页当时的状态，不是所有页面或正常更新状态的统一尺寸。

排行榜原生截图有“选手排行”导航选项和同名页面标题，职责、筛选、排序及记录卡片连续排列；需要重新梳理导航与内容标题层级。不是数据加载或路由错误。

## 设计方向

目的：让观众快速找到当前比赛、选手及其关键表现，同时保留进一步阅读征程和数据的入口。

沿用 Stats 的编辑式赛事风格与既有品牌：纸色 #eeede6、墨色 #181a17、信号黄 #f4c320；数字/标题使用已有 Barlow Condensed，中文使用既有字体与微信可用回退。已有品牌和字体优先于 UI 技能的默认风格，不另建小程序主题。

优先统一调整共用的移动组件与设计规则，再由生成层同步到小程序。微信胶囊/导航、安全区、原生弹窗、滚动及图表绘制的差异在平台适配层处理。Stats 根工作区仍在翻新，实施前核对当时源码与改动归属，不覆盖已有工作。

## 优先优化

1. **首屏与顶部信息**：常态下合并赛事身份、当前状态和更新时间的阅读层级，降低重复说明的占位；异常状态保留明确重试。首页优先让用户看到本周比赛，详情优先看到姓名/队名、核心表现与主要操作。
2. **文字与点击区域**：辅助文字建议以 12–13px 为起点，常用说明采用 14–15px，保留当前大标题和关键数字；页签、筛选、关注和返回有足够点击区域。按四语言和窄屏验证，避免全局放大导致换行或挤压。
3. **数据页面的阅读层级**：区分页面导航、页面标题、职责分类、筛选和排序；降低重复标题的视觉权重。首屏突出名次/姓名/队伍/总评，完整指标按需展开。
4. **人物与队伍档案**：保留黑黄封面、姓名、荣誉、核心数据及英雄形象；整理所属队伍、职责、关注/分享及三个页签的空间关系，让原设计在小屏上更容易读和点。

先打磨总览、赛程、选手/队伍详情与排行，再把确认的共用规则扩展到其他公开页。历史纪念页面保留原有叙事节奏，避免把整站压成一种信息密度。

完成条件：提供同一赛事/身份/语言的 Stats 与原生对照；检查正常/加载/失败、窄屏与四语言、底栏安全区、页签/筛选/返回及长页滚动；用新原生预览包交给用户手机验收。正常显示、操作通过和视觉满意分别记录。

## R10 先修原生适配差异（2026-10-03）

用户继续授权后，先核对平台差异再讨论共用设计修改。本轮未改根 Stats 或 System 的源码。保留既有纸色、墨色、信号黄、人物封面、标题及底栏，调整小程序生成层和原生 Frame。

发现并处理：

- 共用 CSS 中的固定 px 曾二次转换成 rpx。390px 微信视窗中 56px 页头实际为 58px，底栏安全区以上部分也被放大。现在共用移动样式（含提取的对话框）、设计变量及原生边界尺寸保留原单位，响应式 vw/clamp 与安全区 env 继续生效。经典经理等既有独立试验页面仍使用其原编译方式。
- Stats 全局基础文字实为 13px/1.5，档案组件主体另设 15px；原生继承层则硬写 14px。生成器现在读取 `src/styles/globals.css` 的原继承文字规则，避免把所有页面强行改成同一字号。原大标题保持不变。
- 紧凑赛事上下文已显示更新状态和重试，原生仍额外显示一行缓存提示，挤压详情首屏。现在紧凑页只保留共用上下文提示；其他公开页沿用原 DataLayout 通知结构，初次加载失败继续保留重试入口。
- 原生 Frame 补齐原 DataLayout 的目录、赛程、排行、图谱、比赛、队伍档案等路由状态，让原 CSS 对应的页面间距规则实际生效。
- 微信缺少 `wbr`、`caption`、`legend` 等模板，HTML 运行库的 `br` 又产生不适用于微信的 `#text` 节点。共享编译器集中将硬换行/可选断行转成原生 Text，将表格说明、表尾、列元数据及筛选分组标题映射到可渲染容器，保留原文与原选择器类，列元数据仍隐藏。公开 BattleTag 姓名/后缀仍有可选断行机会；阵容和队伍封面的硬换行、排行说明及筛选标题不再缺失。生成测试扫描全部 JSX 分支，按当前微信编译器支持列表检查标签；原生 SVG/图表及选择器消费的数据节点明确排除，不把它们转换成空白内容。

同宽基线分别记录页面内容宽度及视窗宽度，网站桌面模拟器另占 8px 滚动条，不能混为同一个值。R9 基线处于更新失败状态，R10 正常读取状态更短，不能把全部首屏高度差都归因于设计修正。微信系统导航及平台字体回退也与浏览器不同，未承诺跨端逐像素相同。

共用来源哈希和原生实际验证详见 `VERIFICATION.md`。本轮扫码、视觉满意度及真实安卓交互仍需用户确认，R9 正常显示反馈不自动覆盖 R10。
