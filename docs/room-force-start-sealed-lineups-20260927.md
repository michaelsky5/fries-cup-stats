# 首发同时公开与赛管接管开赛

2026-09-27。以下记录本轮实现与发布前验证；生产状态以部署记录和线上验收为准。Stats 与 System 使用分支 `codex/room-force-start-sealed-lineups-20260927`。

## 用户可见行为

- 双方本场操作代表可独立提交本图五人和职责，无需等待选图方。提交后锁定；仅本队能看自己的首发，双方齐全后才向对手、赛管和解说同时公开。
- 未公开时，两侧显示本周候选名单，不把计划首发显示为本图实际首发。公开后按 CCTNN 展示；游戏大厅仍由参赛者按相同顺序排列。
- 支持临场换人和换位，继续验证五人唯一、2 输出 / 1 重装 / 2 支援，以及最新已锁定的本周有效参赛名单。
- 赛管底栏新增“赛管接管 / 强制开始”。用于实际游戏已开始、网页签到或确认未同步的情况，需要公开原因和实际开赛确认。
- 接管不能跳过地图、首发、职责、Ban、资格校验或其他赛管的编辑锁；不会伪造签到，也不会在游戏中点击开始。操作人、时间、原因和接管项保存在比赛沟通与服务端审计中。
- 首发页面单次只编辑一队。赛管可切换尚未提交的队伍，避免双表单挤占高度。操作指南移到底栏，压缩顶部占用。

## 服务端配合

System 新增 `lineupMode: SIMULTANEOUS`、`lineupContext` 与 `startControl`；Stats 对旧接口保留先后提交的兼容展示。`SET_LINEUP` 附带当前地图的上下文，允许双方持同一旧快照并发提交；换图或赛管重开首发后，上下文失效，旧提交被拒绝。

房间读取和导播共用投影均验证未公开阵容的隔离。FD / FCBT 应继续消费过滤后的导播接口，不能从原始工作台草稿获取首发。本轮未运行真实 OBS 或两个桌面导播端。

发布需同时包含 System 与 Stats 的改动。没有数据库结构迁移；首发上下文版本与接管记录保存在现有地图 JSON 中。
