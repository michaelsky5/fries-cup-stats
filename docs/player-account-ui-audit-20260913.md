# 选手详情与账号页面逐项核对 · 2026-09-13

## 结论

选手详情的数据与主要入口已经接通，但桌面信息重复、手机首屏重点和分享预览仍需收尾。账号设置的基本框架可保留；职员身份入口、读取失败与取消状态的表达需要先修复。最新比赛房已有独立的手机布局，不应依据旧审阅样稿判断它尚未完成。

本轮只核对与记录，没有修改产品源码、发布站点、改动真实账号、提交名单、确认赛果或发送邮件。

## 核对范围与证据边界

- 公共页面：`127.0.0.1:3026`，使用本机现有公开赛事数据，覆盖 FCR2026、FCA2026、QGCS4 的代表性选手。主样本完整检查桌面与手机，另外抽查无数据、小样本及跨赛事页面。
- 账号：`127.0.0.3:3047` 的本机审阅服务。目录中 47 个页面/状态分别在桌面与手机打开，检查 DOM、状态文案、链接与可用操作，代表性页面另作截图检查。它们不是 47 个互不重复的业务路由。
- 尺寸：桌面窗口约 1699 × 935，手机 390 × 844。外层页面可用宽度会随滚动条变化。这里不代表已覆盖全部断点、手机实体设备或所有浏览器。
- 账号审阅使用隔离的内存场景，不转发真实 System 写入。重置过期/完成是结果组件样例；未在本轮输入新密码、提交身份申请、发送邮件或执行设备撤销。
- 最新比赛房：`/.codex-tmp/room-ui-upgrade-20260913/index.html`，使用实际比赛房组件与合成状态，九个阶段分别核对桌面、手机；操作代表、队长、选手、赛管、解说在 Ban 阶段抽查操作及沟通范围。此预览不执行业务提交。
- 47 个基础账号状态及九个最新比赛房阶段未发现外层横向溢出。**这不代表所有内部内容都可见**：选手分享预览仍存在容器内裁切。
- 现有 [账号联调记录](account-joint-acceptance-20260913.md) 另有真实 HTTP、数据库和测试部署证据，并记录线上浏览器超时、资料读取及真实邮件等未完成项。本轮没有重新验证这些线上问题，也不以本机 UI 核对替代上线验收。

## 优先修复

### P1 · 手机分享预览只显示部分卡面

复现：打开小狗帅哥的选手详情或分析页，在 390px 宽度点击“分享档案”或“分享数据”。

观察到弹窗约 382px 宽，预览区域约 346px；内部预览框仍约 736px，卡面原尺寸为 1600 × 900。预览区域设置了 `overflow: hidden`，右侧评分和卡面内容被裁掉。页面整体没有横向溢出，因此仅检查 `scrollWidth` 会漏掉此问题。

相关实现：[PlayerShareDialog.module.css](../src/features/player-share/PlayerShareDialog.module.css) 的 `.previewArea`、`.previewFrame`、`.previewScale`。小屏媒体查询仍采用固定宽度和固定缩放比例。

建议：保留导出画布分辨率，预览按容器实际宽度等比缩放；手机先完整展示整张卡，再排列导出控制。分享卡的 `FRIES CUP STATS`、旧评分称谓与图表视觉一起对齐当前赛事中心。此处未验证实际 PNG 导出结果。

### P1 · 解说、赛管的身份申请入口没有接到申请页面

复现：解说/赛管空间 → “前往账号中心申请”。

实际落点为 `/account`。账号页只有账号概览、个人资料、修改密码、邮箱验证和登录设备，没有页面承诺的本届解说/赛管申请表。

相关实现：[EventStaffControl.jsx](../src/features/event-staff/EventStaffControl.jsx) 的 `openAccountCenter()` 与申请说明；[AuthDialog.jsx](../src/features/auth/AuthDialog.jsx) 的 `fries-cup:open-account` 事件将已登录用户导向账号设置。

建议：按当前邀请与身份确认机制接通正确入口；没有可开放的申请流程时，明确显示如何联系赛事方或使用邀请。不应仅保留一个能跳转、却无法完成所述任务的按钮，也不应由此次 UI 收尾自行扩展为公开自助申请。

### P1 · 职员关系读取失败会被显示为“尚未申请”

在审阅服务未覆盖职员关系接口的情况下，页面同时出现“尚未申请”“前往账号中心申请”和读取错误。源代码也确认：初始 `context` 为 `null`，读取异常只设置 `error`；随后空 `participation` 仍进入未申请分支。

相关实现：[EventStaffControl.jsx](../src/features/event-staff/EventStaffControl.jsx) 的 `refresh`、关系状态标题和 `!participation` 分支。

建议区分“读取中 / 读取失败 / 已确认无本届关系 / 已有关系”。读取失败时保留重试，不推断用户没有申请或没有身份。审阅接口未实现属于验证覆盖缺口，不能据此断言正式后端不可用；错误回退的显示问题则由当前代码与界面共同确认。

## 设计与文案精修

### P2 · 选手详情手机首屏缺少赛季重点

主样本手机首屏先经过公共导航、赛事状态、返回和页签，再展示较大的姓名与英雄形象。FMVP 荣誉约在页面纵向 1194px，职责区约在 1279px。分析页的数据对照约从 680px 开始，近期赛况约在 1390px，评分走势约在 2074px。

这些位置是当前样本的观测，不是所有选手的固定高度。问题在于读者较晚才看到“这是谁、这一季做到了什么”。

建议手机先展示姓名、队伍/职责、关键赛季数据和荣誉，英雄形象作为辅助；保留“档案 / 分析”两种用途。桌面继续沿用人物与英雄展示方向，合并职责卡、英雄下方与页尾反复出现的地图/比赛数量。分析页近期比赛与评分走势中重复的比赛列表也应收束，保留一个主要浏览入口。

相关实现：[SignalPlayerDossier.jsx](../src/features/player-dossier/SignalPlayerDossier.jsx)、[SignalPlayerProfileSections.jsx](../src/features/player-dossier/SignalPlayerProfileSections.jsx)、[SignalPlayerAnalysis.jsx](../src/features/player-dossier/SignalPlayerAnalysis.jsx)、[SignalPlayerRatingJourney.jsx](../src/features/player-dossier/SignalPlayerRatingJourney.jsx)。

### P2 · 无出场数据的分析页重复展示空内容

`dontsmile` 的档案明确没有已发布出场记录，评分也正确使用未评级状态。分析页仍连续保留空对照、空近期赛况和空评分走势。

建议整合成一块“尚无已发布出场数据”，保留队伍、登记身份和返回入口；不要用零分或推断的英雄填补缺失数据。

### P2 · 已取消参赛仍沿用提交前的版式与文案

`cancelled` 场景中的五名已保存队员正确不可编辑，但页面上部仍显示“本周参赛准备”和未提交步骤，名单后出现“提交前核对”“当前为已保存草稿，正式提交后交由周赛管理员锁定”。“赛事安排已取消，已有记录仅供查看”位于整份名单之后。

建议把取消原因与只读状态放到名单之前，标题改为保存的名单记录，并移除无法继续执行的下一步文案。已提交状态已有“等待锁定”的说明，但检查区标题仍可从“提交前核对”改为“已提交名单”。

相关实现：[WeeklyCompetitionWorkspace.jsx](../src/features/weekly-competition/WeeklyCompetitionWorkspace.jsx) 的名单核对区；[weeklyPreparationModel.js](../src/features/weekly-competition/weeklyPreparationModel.js) 的终态说明。

注意：页面初始读取时短暂出现的空人数在同步完成后会更新为正确人数，本轮没有把这种过渡状态记录为持续的数据错误。

### P2 · 账号手机页面的标题与说明占用偏多

- 名单页在实际内容前重复公共导航、我的空间、赛事身份、当前栏目、参赛分区、准备标题和步骤导航。
- 消息页在“我的空间 / 当前栏目 / 赛事消息”后又展示较长说明；只有一条消息时，仍保留首要消息、摘要数字、消息与任务的分工、其余消息的空状态。
- 进行中的比赛仍保留大块“房间与准备”和提前核对说明。它已正确撤去不适用的准备操作，但视觉重心可以进一步转向当前比赛与沟通。

建议保留一层上下文导航和一个当前任务标题。消息直接呈现未读/全部、正文与下一步入口；取消“不会混入任务队列”等内部设计解释。进行中页面将赛前信息折叠为准备记录。

账号设置的五个主要分区框架可保留，重点精简重复说明，不需要整体翻新。

### P2 · 账号审阅目录仍链接到旧比赛房样稿

[accountReviewCatalog.js](../src/pages/dev/accountReviewCatalog.js) 的 `room-stages` 仍指向 `/dev/account-preview?embed=1&view=room`，这是旧 FT3 阶段样例；当前周赛实际组件已是 RR5 固定五局。

从审阅账号的真实比赛入口进入 `/me/matches/preview-weekly-next/room`，本机 3047 服务未覆盖对应比赛房接口，会展示“本地设计预览未模拟此操作”。此结果只说明该审阅服务未覆盖路线，不能当作正式比赛房功能故障。

应更新审阅目录，区分旧概念样稿、实际组件场景和真实 API 联调，防止用旧页面做发布判断。

### P3 · 少量中文阶段名称仍保留英文

中文选手比赛记录出现“季后赛 · LB Final”。[playerDossierPresentation.js](../src/features/player-dossier/playerDossierPresentation.js) 的翻译表使用 `LB FINAL`，分段查找没有规范大小写。

建议在阶段枚举查找时统一大小写，未知名称仍原样保留，不改写选手、队伍等专名。账号关注记录也有 `QUALIFICATION / ROUND OF 16` 等原始轮次，适合在同一轮文案核对中处理。
