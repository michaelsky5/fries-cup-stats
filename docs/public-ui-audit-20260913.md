# 公开 UI 复核与下一轮精修建议

日期：2026-09-13。性质：视觉与信息表达审阅；本轮未修改页面实现。

## 结论

六个主栏目已经形成共同的纸色、墨黑、黄色、直角与目录导航语言。下一轮应优先解决内容量变化时的布局、详情页的公共区域和旧文案，而不是重新设计所有主页面。

用户截图中周赛总览的右下空白没有信息含义：焦点比赛和本周全部对阵都在左栏，右栏的积分先结束，整行高度却继续由左栏决定。它不是缺失数据的占位，也不是一个尚未加载的模块。

## 周赛总览的推荐布局

桌面分为三个连续区块：

1. 上方为焦点比赛与周期积分，两者按内容调整密度。
2. 下方将本周全部对阵独立为通栏，继续使用便于比较状态、时间、双方和比分的比赛行。
3. 关注队伍放在更紧凑的独立区块中，接续周赛路径说明。

只改变列宽或者强制两栏等高都不能解决问题：对阵数、积分队伍数改变后，空白仍会转移。上方两栏也应避免用大段 padding 补齐高度。三个区块之间用现有细线与间距划分即可。

手机目前按焦点比赛、本周对阵、周期积分、关注队伍依次堆叠，没有桌面的右下空洞。实施时应保留这个阅读顺序，并按实际内容决定各区块高度。

备选方案是将现有的关注队伍移入积分下方，取消下方重复的大关注区。但它的高度仍取决于队伍数量，稳定性不如对阵独立通栏。这里不需要新增英雄动效或无关模块来填充空间。

布局依据：`src/features/weekly-overview/SignalWeeklyOverview.jsx:61`、`:86`，及同目录样式文件的 `.mainGrid`。1699 px 桌面窗口下，本次样例左栏约 951 px、右栏约 728 px，右侧约有 223 px 的剩余高度；样例只有三场对阵。

选手分析的比赛走势区也存在左侧图表内容少于右侧逐图详情时的剩余空间，可随“少量内容布局”一并复核。它的优先级低于两英雄图鉴的宽面板。

## 适合保留的部分

- 参赛阵容总览、队伍目录、选手目录、战队职员与赛事职员：公共框架已经统一，内容差异有用途，保留主体构图。
- 有数据的选手排行、更多筛选和评分依据弹层：保留当前信息分组与直角交互，不再增加重复的筛选提示行。
- 英雄索引、英雄详情、地图索引：保留索引与预览之间的联系。地图索引右侧卡片会随滚动保持可见，不能把整页截图下方的空白误判为无用区域。
- 归档赛程精选、比赛详情、队伍竞技分析速览：主次和浏览路径成立，先做共同组件与文案的局部精修。
- 归档首页与队伍展厅：叙事和人物图像有实际主题，允许比进行中的赛事页面更有展示感。不要把展示型页面与数据目录强行做成相同构图。
- 登录与管理关注弹层：已沿用直角、黑黄与清晰的操作分组，本轮未发现需要整体推翻的视觉问题。

## 范围边界与下一轮验收

这是主要公开页面及代表性详情、弹层的 UI 审阅，不是全部状态的发布验收。本轮未完成所有英语页面、全部赛季组合、所有筛选排列、回顾全部故事章节，以及登录后的账户、报名、比赛房操作流程。Fantasy 和私密 scouting 路径不在本轮公开主链的逐页视觉复核内。

下一轮建议先实施周赛总览重组和当前文案/控件修正，再处理关注摘要与少量英雄布局，最后将详情页公共区域纳入统一组件。完成后针对涉及组件复核宽屏、窄屏、手机、中英文、空数据与少量数据；不以一次构建成功替代视觉确认。

本轮仅新增这份审阅记录，未修改产品代码，未部署，未重新执行与代码变更有关的构建或自动化测试。
