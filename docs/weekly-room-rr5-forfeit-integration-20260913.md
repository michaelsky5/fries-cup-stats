## 规则与产品行为

规则书第 3.1 条已经明确小局弃权的 0／1 分，第 7.3 条规定中途全场弃权方当周 0 分。本轮确认的执行口径是：对手保留已完成地图的积分，再按每张未完成地图 1 分计入；平局占一张已完成地图，双方各 1 分。详见 [规则执行说明](weekly-room-rr5-forfeit-supplement-20260913.md)。这不是新增积分标准，不需要为此另设规则发布门槛。

赛管记录全场弃权时，先选队伍、查看预计积分、填写公开原因。提交后停止后续选禁、开赛与记分，显示“弃权待复核”。管理员可确认或撤回；确认后再开放队伍核对，最后结算。

未齐双方确认或存在争议时，管理员可明确选择“按裁定结算”，填写依据后提交。该操作保留原响应快照及审计信息，公开记录裁定说明。前端不允许手改弃权积分，服务端也拒绝不符合规则的积分。

页面分别展示实际地图比分、全场弃权判定和周赛积分。未完成地图不显示假小分或选手数据。待复核积分标明“拟计”；按裁定结算后的步骤显示“响应已裁定”，不会冒充双方确认。关键比分与积分直接可见，详细原因和复核记录可展开；管理员复核弹窗默认展开依据，使用现有纸白操作区色彩。

撤回尚未批准的弃权记录会保留选禁及地图进度。若原地图仍在进行，会先进入暂停核对，双方确认恢复条件后由赛管恢复；不会自动继续游戏。

## 数据与权限保护

- Match 行锁及 Serializable 事务内重新检查会话、身份、赛事权限和当前版本；赛管可记录，本届管理员负责复核。
- 同一次提交复用幂等编号；重复请求不会重复生成裁定、地图或积分流水。旧版本、旧响应、撤销的赛管指派均会被拒绝。
- 复核使用提交时的地图内容指纹。正式地图、地图类型、胜者、比分或 Ban 与裁定依据冲突时阻止覆盖，要求先核对。
- 只将已经完成的真实工作地图及 Ban 保存为正式记录。开赛前弃权保留空比分和零张正式地图，不伪造 0:0、5:0 或地图表现。
- 积分流水记录规则版本、完成与剩余图数、实际得分和是否按裁定结算。非积分周期仍按现有约定记双方 0 分。
- 审核或结算后资料发生变化会进入 RECHECK，冻结直接结算。本轮新入口支持批准前撤回；已批准裁定的改判及重新复核，后续需专门衔接到比赛房。已结算记录保留既有积分冲正服务，不能直接覆盖积分流水。
- 此分支使用既有 JSON 与账本字段，不新增弃权专用迁移；RR5 枚举仍依赖上一轮 `20260913_rr5_match_format` 迁移。
