# 我的空间：站内参赛协作与交互收拢

2026-09-11。本机实现和验证，未提交、未推送、未部署。

用户方向是通过网页完成参赛事务，参赛者和赛管在同一套记录里交接。本轮补的是赛前安排、队伍准备确认、问题受理和回执，不把群聊或私下联系作为这些操作的出口。

## 本轮变化

- 我的空间压缩身份和赛事栏；正常同步状态折叠。首页优先显示待办和下一场比赛。导航中的待办由各栏目共用的真实来源计算，直接进入比赛页也能得到相同数量。
- 周赛准备一次展开一个步骤，保留明确的周期、队伍、周次和截止时间。只读名单显示已保存人员；撤回当周参赛需要单独确认；保存回执留在当前步骤。
- 我的关注分为「近况与关注对象」「全部关联比赛」。对象筛选和当前视图保存在地址中，返回仍可继续查看。队伍卡片显示名次与关联比赛数，不再复制首屏比分。
- System 的「赛程安排 → 参赛协作」可发布每场房间名称、口令和说明。只有相关队伍和本赛季赛管能读取。
- 队长或经理核对安排后确认本队已准备好。双方与赛管可查看；可撤回；比赛不会自动开始。房间安排、比赛修订或本队名单变化，会使旧确认失效。
- 房间发布后，准备确认进入首页待办；确认完成后移出待办；重新需要确认时重新出现。
- 参赛准备和比赛页都可提交协助请求。赛管受理、回复、解决，参赛者在原记录查看结果。补充已解决的问题会重新打开；历史回复保留。
- 网络失败保留输入和提交编号；原样重试不重复建单。多人处理使用版本检查；房间表单遇到新版本会保留输入并要求载入最新安排。未保存内容受公共导航保护。

视觉依据为 `fries-cup-design-system.md` v1.1、`fries-cup-data-signal-design-system.md` v2.1，以及 System 的 `ui-design-principles.md`。Stats 使用纸色、深色任务区和黄色主操作；System 保持自己的深色控制台。
