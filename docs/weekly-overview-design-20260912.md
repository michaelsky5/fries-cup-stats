# 周赛进行中总览 · 2026-09-12

状态：本地设计首版，使用明确标注的合成赛程和积分。未发布，也未把样例队伍视为已报名周赛。

## 依据

- [官网周赛专题](https://fries-cup.com/events/weekly/)及其 V1.6.1 规则：RR5 固定打满五局，常规完赛每图胜 2 分、负或平 1 分；每周比赛累计周期积分，后接周期双败季后赛与 Weekly Major。晋级名额、日期以当期公示为准。
- System `server/src/lib/weeklyPublishSnapshot.js` 的 `friescup-weekly-public-v1`：仅公开 ACTIVE / PLAYOFFS / CLOSED 周期和 PUBLISHED / IN_PROGRESS / RESULT_REVIEW / CLOSED 周次，附已公开比赛 ID 与周期积分。
- System `server/src/lib/publishBuilder.js`：公开比赛包含 `match_id`、`raw_match_id`、`cycle_id`、`cycle_week_id`、实际比分和地图记录。
- 既有 FC Signal 规范：进行中首页采用 Index，延续纸色、墨色、品牌黄、直角、分隔线、双语标签与清晰数字。

## 首版结构

1. 赛事上下文与短标题；周期选择和官网参赛说明位于标题右侧，手机转为下一行。
2. 已发布周次导航：整格可选、当前周黄色下划线。默认优先进行中周，其次审核中、已公布周，最后为最近结束周。
3. 主对阵：队徽、队名、状态、公开比赛时间、比分和固定五局记录。3:0 不触发完赛，待赛显示 VS，缺少比分保留破折号。RR5 以外赛制不生成五局占位。
4. 本周全部对阵：点选更新主对阵；主对阵在视野上方时回到该区域。比赛详情可返回原周期、周次和对阵。
5. 周期积分：直接呈现已发布行次、并列、已赛场数和积分。切历史周仍展示周期最新公布积分，明确标注；不从实时比分计算官方积分，不推算晋级线。
6. 关注队伍使用既有关注能力；默认焦点优先关注队伍的进行中比赛。用户明确选择的比赛优先。
7. 页尾简述每周比赛、周期季后赛与 Major 的关系；资格和日期留给当期公示。

地图的空占位不表示该局已经开始。行政判定与正常地图记录分开表达。`counts_toward_standings=false` 的周期保留比赛记录，不生成积分排名。
