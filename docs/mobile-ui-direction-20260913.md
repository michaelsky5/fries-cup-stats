# 手机 UI 方向与首版记录

日期：2026-09-13。

用户指出手机「像桌面缩小版，手机上的重点不清楚」。本轮完成共享导航、归档首页入口和选手排行的第一版重排，供本地体验评审。桌面继续沿用已经形成的 FC Signal 布局。未发布，也未完成全站手机重设计。

## 阅读顺序

| 场景 | 手机首先回答的问题 | 首版处理 |
| --- | --- | --- |
| 页面导航 | 我在哪，接下来去哪 | 顶部保留品牌、赛事与账户；底部固定总览、赛程、阵容、数据和更多 |
| 已归档赛事首页 | 谁夺冠，决赛怎样，从哪里继续看 | 冠军队伍 → 决赛 → 赛果与阵容入口 → 冠军人物；赛季故事随后展开 |
| 选手排行 | 找谁，他的名次和表现怎样 | 职责、搜索、正式排名开关、排序摘要紧接选手记录；详细设置进入抽屉 |

保留墨色主区、纸色记录区、黄色选中信号和直角控件。改变的是阅读先后与操作位置，评分、样本门槛、赛事状态、名单与英雄来源仍复用已有逻辑。首页人物优先使用已记录的总决赛 MVP，没有时展示冠军成员，不补造奖项。

## 实现范围

- `PublicMobileNav`：600px 及以下启用五项底部导航。「更多」展开全部六个公开分区与现有语言选择。路由和语言变化关闭抽屉，保留赛事及已有周赛上下文。
- `PublicHeader` / `KprShell`：手机公开页面采用 56px 顶栏，为底部导航和设备安全区留出空间。账户、参赛任务、比赛房间及开发页不套用公开导航。600px 以上保留既有桌面和平板导航。
- `MobileSeasonArchive`：紧凑冠军卡、真实决赛比分、赛事入口和冠军人物。手机隐藏桌面首屏舞台，并停止该舞台的滚动切幕与指针监听；隐藏舞台中的英雄图不再强制优先加载。下方原有赛季章节继续保留。
- `MobileRankingControls`：复用排行榜状态、回调与 URL 参数。队伍、英雄、出场分钟、关注、排序、口径、完整表格和列选择集中在原生对话框构成的底部抽屉。筛选即时生效，底部按钮用于返回结果。
- 正式排名开关留在固定结果行，不生成单独标签行。手机完整表格仍允许内部横向滚动。比较栏避让底部导航。
- `design=original` 保留旧版界面，不出现新增手机控件。

主要源码位于 `src/components/layout/PublicMobileNav.*`、`src/features/kpr-design/MobileSeasonArchive.*`、`src/features/kpr-design/MobileRankingControls.*`，以及各自接入的 Header、Shell、Archive 和 Leaderboard 文件。

## 同日页尾修复

归档首页结束后出现浅色空白的原因是外层 `DataLayout` 额外追加更新时间，页面容器又保留通用底部间距。本次仅对已归档的新版普通赛事首页设置独立收尾：更新时间与数据来源状态进入 `KprImmersiveArchive` 的深色版权栏，外层取消重复状态行和底部间距；手机底栏避让空间由深色版权栏内部承担。状态继续复用 `getPublicDataStatus`，不会把刷新中或更新失败误写成已更新。

有赛季回顾主卡片时，尾部移除重复回顾链接；没有回顾的赛事保留赛果链接并使用「赛程赛果 / Match results」。

本次 FCR2026 简体中文检查覆盖默认桌面、980px 与 390px：版权栏底部与文档底部一致，没有外层横向溢出；390px 的更新时间距底部导航约 20px。QGCS4 英文页尾保留正确时间与赛果入口。针对改动的 ESLint、空白检查、公开入口 5 项和周赛总览 18 项现有检查通过，隔离 Vite 构建通过。产物与改前文件保存在 `tmp/archive-footer-fix-20260913-120451/`，未发布。
