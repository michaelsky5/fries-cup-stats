# 周赛比赛房：真实流程第一段

日期：2026-09-11。状态：本机实现与独立数据库演练通过；未发布到正式环境。

## 本轮交付

新版入口为 `/me/matches/:matchId/room`，位于公开赛事快照布局之外，使用现有账号登录和 System 的真实周赛接口。我的比赛卡片和 System 周赛协助面板增加了入口。旧 `/matches/:matchId/room` 保留；修正其后台同步失败被忽略的问题，并按最近成功同步时间显示状态。

一页保留比赛身份、双方名单、当前图、当前任务、中央沟通与整场地图。采用 2026-09-10 品牌规范及赛事中心 Control 模式：墨黑工作区、黄色当前操作、独立比赛进行与暂停状态色，地图和英雄名称复用现有中文映射与本地素材。

本轮接通：双方代表确认准备 → 赛管记录游戏开赛 → 队伍私密求助 → 赛管受理 → 赛管记录公开暂停 → 双方代表确认恢复 → 赛管记录游戏恢复。公共消息、私密协助和转播协同分别保存、分别授权。网页记录人工确认的游戏状态，不直接控制游戏客户端。

## 数据与身份

| 内容 | 数据来源及约束 |
| --- | --- |
| 地图、禁用、当前图 | 现有 System `MatchOperationsDraft`；开赛写回同一工作台记录 |
| 两侧名单 | 本周已提交/锁定的 `WeeklyRoster`，明确标为计划首发，不当作当前图实际阵容 |
| 赛前准备 | 现有 `WeeklyTeamReadiness`，校验房间/名单指纹并展示实际确认人 |
| 私密协助 | 现有周赛协助表；只有相关队伍与本场赛管可见 |
| 暂停与恢复 | 新增 `WeeklyLiveControl`，校验比赛、工作台和控制版本及地图身份 |
| 公共/转播沟通 | 新增 `WeeklyRoomMessage`，按账号与提交编号防重；保存不等于已读 |
| 解说准入 | 新增本场 `WeeklyRoomCaster` 指派；同时要求有效身份与本届账号准入 |

队长/经理能代表本队准备与恢复；选手、教练可查看、沟通和请求协助，不能代表队伍签署。只有本场赛管或周赛管理员记录开赛、暂停、恢复。解说只见公开比赛信息和转播协同。每次写入在事务内重新验证账号、会话、当前成员关系及指派；其他赛管仍在主编辑租约内时必须先交接。

## 本机实际验证

- 新增真实 Cookie + Fastify + PostgreSQL 检查 11/11 通过：身份、准备失效、开赛前置条件、私密范围、暂停恢复、重复提交、并发、事务内撤权、解说撤回、工作台租约与地图变化、增量迁移。
- 原周赛协助数据库回归 7/7 通过；原 Stats 周赛房间、Cookie 登录、请求超时与取消检查通过。
- 四个独立浏览器账号实际操作本队经理、对方队长、赛管和解说。数据库回读确认 `START → PAUSE → RECOVER → RECOVER → RESUME`，控制版本为 5，工作台当前图为 LIVE；私密协助 3 条消息且已解决，公共消息 6 条、转播消息 1 条。公开消息不含私密求助正文。
- 解说在另一个页面重新读取到已保存转播消息；对手页面无转播入口，也没有转播正文。
- 503 故障时保留上次数据与草稿、显示错误、禁用发送。5 秒慢响应能完成同步，未被 3 秒轮询反复取消。403 时移除房间缓存；恢复后自动重新读取。刷新页面仍保留按账号、比赛、范围、请求及地图区分的草稿。
- 1280×900 的进行中房间文档高度 900；2048×1080 文档高度 1080，地图栏与输入区无覆盖。390×844 下文档宽 382（扣除滚动条），任务/沟通在前、名单在后，保持同一页面。展开沟通后隐藏当前任务，沟通区约 641px，无横向溢出。
- 联调发现并修复了小高度窗口底部栏覆盖提交按钮的问题。开发热更新曾因 Hook 数量变化进入错误边界，完整载入新代码后恢复；后续冷启动、构建与新页面检查通过。
- Stats 生产构建通过。新增前后端文件 ESLint 无错误或警告；旧比赛房仍有 6 条原有 Hook 依赖警告。

证据文件位于 `.codex-tmp/live-room-20260911/`。System 同名目录中的 `browser-database-evidence.json` 保存真实浏览器操作的数据库回读；自动化报告分别位于本机临时目录 `friescup-registration-postgres-U27sYE` 与 `friescup-registration-postgres-lZsqny`。
