# 账号头像 · 2026-09-14

已完成本机与公网测试验证，试用地址为 https://hub-preview.fries-cup.com/account?lang=zh#profile 。尚未发布到正式环境。

## 使用

个人资料 → 更换头像 → 英雄头像 / 上传图片 → 使用这个头像 → 保存资料。

53 位英雄支持中英文搜索和职责筛选。自定义图片支持方形裁剪、缩放、横纵位置调整。应用头像只更新草稿；保存资料才提交。取消、撤销、恢复默认都有明确反馈，失败时保留表单与原头像。顶部账号入口、资料预览、账号概览、我的空间和比赛交流统一显示，图片失败回退到姓名缩写。所选英雄不会覆盖统计中的常用英雄。

## 资源和数据

复用 UserProfile.avatarUrl，无数据库迁移。PATCH /api/me/profile 的 avatar 命令与其他资料在同一事务内保存，事务内重查身份、状态、权限和会话。

原图 ≤2 MiB / 1600 万像素，仅 JPEG、PNG、静态 WebP。服务端检查实际格式、拒绝动图、修正 EXIF 方向并移除元数据；生成 256×256 与 96×96 WebP，分别最多 100 KiB / 30 KiB，不保留原图。每账号 10 分钟最多 5 次上传尝试，单进程同时处理 1 张图。正常替换删除旧图，事务失败删除本次生成文件；异常退出后的孤立文件仍需运维清理。

媒体接口使用严格路径、随机版本文件名、public immutable 缓存，不返回账号资料。文件写入现有 UPLOAD_DIR/avatars，部署已配置 uploads 持久卷和备份；Nginx 25 MiB 上限足够。Sharp 0.35.4 已加入依赖和主工作区安装。

EdgeOne 隔离候选的头像路径单独缓存，不带凭据；只有资料 PATCH 请求上限调整为 3 MiB，其他写接口保留 1 MiB，账号接口继续 no-store。预览专用代理和对应测试保留在候选分支，不引入主工作区的发布配置。

## 第二轮：跨页面同步与协助

保存资料后发送不含身份或凭据的失效通知，各页面使用当前登录会话重新读取资料。顶部账号显示与资料预览同步；未编辑字段跟随最新资料，正在编辑的字段、主动清空昵称和未提交头像保留，并提示核对。旧的身份请求不会把头像恢复为旧值。我的空间邮箱提示点改为头像内部定位，避免裁切。

赛管协助的私有线程返回作者头像，Stats 比赛房与参赛协作页统一展示；只读取头像字段，不增加邮箱、介绍或跨队权限。无头像保留姓名缩写。

本轮验证：账号设置与入口检查通过；真实 PostgreSQL 赛前协作 7/7、比赛房回归 27/27；Stats 构建通过。Edge 两个页面实测头像和名字双向同步、脏表单保留、刻意清空字段保留、保存后不覆盖另一页未编辑字段。实际合成队伍提交协助、合成赛管回复后，双方头像均加载为 28×28；390×844 无页面横向溢出。

以上是第二轮本机证据；本次公网测试也已包含这些补充，正式站未更新。
