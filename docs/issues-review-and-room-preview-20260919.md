## 清单核对

| 问题 | 实施与验证 |

| 我的空间缺少报名入口 | 队伍区域统一进入 `/participate/:seasonId`，遵循赛事开放权限；旧报名编辑器不再混用。 |

| Logo 上传 | 正式表单接入上传、错误提示和预览；真实接口上传项目 PNG、保存并提交成功。用户原先失败的图片未提供，不能宣称该特定文件已复测。 |
| 报名错误不明确 | 展示服务端字段级问题、必填资格项，错误区支持焦点定位。 |

| 提交成功不明显 | 成功状态区明确提示已提交、等待审核、无需重复操作；真实提交浏览器验收通过。 |
| 本人确认与队伍提交混淆 | 本人成功提示仍需负责人提交；负责人展示人数、报名步骤及最终提交动作。 |

## 比赛房

- 唯一正式房间 `/me/matches/:matchId/room`；开发预览直接复用 `WeeklyRoomView`，只有只读示例数据和阶段选择器不同。
- 顶部比赛信息与地图进程、两侧队伍名单、中间唯一当前操作页。聊天、规则、历史和异常处理按需打开弹层，不挤占常驻操作空间。
- 每图选择五位首发并确认本图职责，允许临场换位；前后端都验证五人唯一和 2C/1T/2N。持久保存并按 C、C、T、N、N 展示，开赛核对明确要求游戏大厅也按此排序。
- 首发按选图方先、对方后提交；双方提交前隐藏对方本图阵容，提交后锁定。Ban 后不可偷偷更换，赛管纠正需走明确流程。
- 实际 1V1、选图、首发、Ban、准备核对、开赛、暂停恢复、本图结果、下一图联通真实服务端；缺少赛管时使用后端明确授权的操作代表，不放宽全站玩家写权限。
- System 后台可保存实际 1V1 规则；赛管准备操作带服务端版本指纹。首图限定控制图，RR5 平局完成一图但不计一胜。
- 首屏有独立加载层，初始路由与首屏样式准备期间暂停入场动画；资源等待有上限，慢加载提供重试，不伪造百分比。
