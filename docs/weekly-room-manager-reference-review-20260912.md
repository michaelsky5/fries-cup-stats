# 比赛房视觉复核：经理游戏的决策页面

日期：2026-09-12。独立设计研究与可点击样稿。使用者已认可 02 版方向，03 版继续完善交互状态；原产品代码、接口及数据库未在这两轮修改。

## 为什么上一轮仍不成立

对照当前真实演练页 OPENING1-M1 的 1440px 桌面画面，问题是信息层级和比赛对象的呈现：

1. 当前任务、流程、模式、说明、双方状态、选项和确认都呈现为相似的横条。纸色面积增加，但没有相应的主次。
2. 比赛对象偏弱。队徽缺席，地图与英雄的辨识作用不足，文字和边框承担了过多解释任务。
3. 名单、代表说明与准备提示反复占用纵向空间；次要说明与真正需要关注的下一步同时争夺注意力。
4. 顶部比赛身份、当前图和整场地图记录不够连贯，用户需要在上下区域拼接本场进度。
5. 前一轮的权限、回归和构建结果证明功能边界，不代表视觉体验已经获用户认可。

## 品牌与视觉试验

依据当前 [FC Signal 实现规范 v2.5.17](fries-cup-data-signal-design-system.md)，继续使用墨黑 #181a17、纸白 #eeede6、信号黄 #f4c320，以及既有二级表面色。没有把外部游戏的辅助色当作新的主题。

- 放大队伍、比分与选中对象，用现有 Barlow 字体、队徽和地图/英雄图建立视觉层级。
- 当前决定使用一块纸色工作区，减少嵌套边框与重复说明。地图以图像卡呈现，Ban 以候选英雄和选中英雄预览呈现。
- 确认区固定在操作区域底部，复述“地图 + Ban 顺序”或“禁用英雄”，再执行确认。
- 双方名单保留同页，代表缩为紧凑身份行。完整规则及交接记录按需展开。
- 比赛沟通区保留置顶赛管说明、最近消息和发送入口。
- 深色辅助字收敛为中性灰阶；黄色用于当前信号与提交，选中的大面积对象不整块涂黄。

## 本轮用户确认：周赛为 RR5

用户明确选择：**周赛按 RR5，固定打满五局。**

样稿增加固定五局记录，规则中明确 3:0 不提前结束，第 4、5 局仍须完成。先手权和代表生命周期沿用已确认规则。

这是赛制与样稿展示的确认，本轮没有把原 OPENING1 FT3 演练库直接改成 RR5，也没有修改正式比赛的推进/完赛服务。正式接入时需把周赛配置、比赛房展示与结束条件一并核对，不得把这份视觉研究当作 RR5 后端验证。

## 本机检查

- JavaScript 语法检查通过；此轮是独立静态样稿，没有运行或宣称产品后端回归。
- 实际试用地图选择、Ban 顺序、确认反馈、英雄选择、石头剪刀布未选/已选状态、规则对话框和查看者权限展示。
- 查看了 1440×1080、1280×900 和 390×844。没有发现页面横向溢出、破图或浏览器错误。
- 1280×900 的地图样稿中，沟通输入底部约在 854px；补充记录和页尾仍可能需要纵向滚动。手机优先展示当前操作，名单继续位于同一页面下方。
- 顶部工具按钮桌面均为 136×40px；手机改为同为 40×40px 的图标入口，并保留可访问名称。

以上为 02 初版的设计与验证记录。使用者随后确认“方向是对的，现在这个好看多了，在这个基础上多优化就行了”，继续完善如下。

## 03：在认可的方向上完善交互

仍在同一预览地址查看。保留三栏构图、居中比分、黑黄白配色和同页比赛沟通；02 版文件保存在 .codex-tmp/room-design-polish-20260912/approved-02/。

- 补齐“先手权 / 选图 / Ban / 准备确认”四个独立示例。选择地图、Ban 顺序和英雄后，在后续阶段沿用同一对象；修改上游选择会清除受影响的核对状态。
- 完成态收起不可操作的候选列表，用地图或英雄结果卡呈现锁定对象，并注明下一步由谁完成。石头剪刀布保留本队出手与等待对方的状态，不伪造对方结果。
- 准备页汇总地图、双方禁用与三项代表核对。完成前不能确认，完成后显示等待赛管开赛，不表示游戏已自动开始。
- Ban 从仓库英雄目录展示 53 名英雄，支持职责筛选、中英文搜索、空结果恢复；第二手示例中已禁用职责不能再选。目录用于交互展示，不等于已确认的赛季可用英雄配置。
- 切换成员视角保留选择和锁定状态；成员只能浏览。浏览另一地图类型不会悄悄改变代表已选地图。
- 公共交流提供本页消息回显、完整记录查看和草稿保留。赛管协助提供问题概述、具体情况、待处理记录和补充消息；对应本队与赛管范围，不混入双方公共交流。
- 桌面顶部工具按钮保持同为 136×40px；手机改为同为 44×44px。手机辅助文字与当前阶段断行继续调整，规则和记录按需展开。

### 03 本机检查与边界

检查了 1920×1080、1440×960、1280×900、390×844 的页面；手机四个阶段均无外层横向溢出。实际试用地图选择与锁定、职责限制、英文搜索、空搜索恢复、代表/成员视角、准备核对、公共消息、频道草稿、协助建立与补充对话。

53 名英雄的头像及展示图共 106 个本地文件均存在，JavaScript 语法检查通过。1280×900 下，地图锁定、Ban 锁定和准备完成示例的沟通输入底部分别约为 840、860、873px；准备核对未完成时约为 904px。完整名单、补充记录、较长消息或其他状态仍可能需要纵向滚动，不宣称所有内容均在一屏内。

这些是独立样稿的浏览器检查。所有交互仅存在于当前页面，刷新后重置；没有发送真实消息、通知赛管或推进比赛。未替换正式比赛房，未验证 RR5 正式推进服务，未发布。
