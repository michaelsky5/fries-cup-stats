# FD 数据站设计预览 · 第一轮

本轮以 FryDeck 薯条杯版 Overlay 为主要参考，保留现有队伍详情的信息结构和全部数据口径。提取的视觉规则是黄黑白、人物展示区与纸质档案区的对照、清晰的数字层级、细分隔线和少量切角；黄色只用于品牌、当前选择和重要数值。

## 预览入口

- 队伍详情：`http://127.0.0.1:4187/teams/FCR26-T026?season=FCR26&design=fd`
- 数据排行：`http://127.0.0.1:4187/leaderboard?season=FCR26&design=fd`
- 英雄裁切画廊：`http://127.0.0.1:4187/artifacts/fd-design-preview-20260831/hero-gallery.html`

页面顶部可以切换「FD 新版 / 原版对照」。`design=original` 或不带 `design` 时保留原有样式。设计切换保留赛事、搜索和筛选条件；主导航保留赛事与设计版本，清除不属于下一页的筛选条件。

开发服务器使用：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4187 --strictPort
```

## 本轮范围

- 共享页头、赛事切换、语言入口、手机导航和加载状态。
- 队伍详情的主视觉、关键数据、核心五人、完整名单和场景背景。
- 排行榜的榜首档案、三个职责的领跑选手、筛选和表格。
- 其他页面保留原有浅色内容区，避免尚未迁移的深色文字落在黑色背景上。

原有赛程、战术数据、OVR、关注、比较和分享图逻辑继续使用。没有改动统计公式、接口、认证、赛季发布或数据文件；分享图仍使用原来的导出卡面。

下一轮可按「赛事总览 → 选手详情 → 赛程与比赛详情 → 英雄和地图数据」逐页迁移。当前预览没有改变站点默认样式，也没有上线。

## 实现边界

`src/features/fd-design/` 保存设计变量、样式适配器和预览入口。适配器组合原有 CSS Modules 与 FD 类名，所有 FD 规则限定在 `data-design="fd"` 内。

`DataLayout` 通过 URL 开关传递 `isFdDesign`，并用 `data-fd-page` 区分已经完成的样板与尚未迁移的内容页。原有页面和模块没有整块重写。

此工作区在开始前已有大量未提交修改。本轮涉及的 19 个原有文件已逐个保存到 `artifacts/fd-design-preview-20260831/baseline/`；`integration-diff.patch` 是相对于这份快照的改动，不应把整个工作区的 Git 差异当作本轮改动。

## 英雄素材

- 来源补充（2026-08-31）：用户确认本轮 FD 英雄素材均由本人在《守望先锋》游戏内截图取得；透明素材不应再被记作来源不明的网络图片或未经确认的官方透明 PNG。
- 图片使用条件与加工方式见 [素材使用记录](./design-material-policy.md)；来源确认不等于转让游戏美术版权或授予任意修改、再分发权利。
- 共 53 位：15 重装、24 输出、14 支援。
- 原始透明 PNG 位于 `public/review/hero-renders/`，逐文件核对与 FryDeck 原图一致；未覆盖原图。
- 网页使用 `public/hero-artwork/` 中 640 / 1280 两档 WebP，共 106 张，合计 4,941,502 字节。两档合计约 4.71 MiB；页面只加载实际展示的人物。
- `src/components/media/HeroArtwork.jsx` 负责响应式加载、人物焦点、顶部留白和错误回退。
- `src/data/heroArtworkProfiles.js` 沿用 FD 的人物裁切参数；英雄名称先通过现有英雄注册表解析，避免名称、ID 和文件名混用。
- 加载失败按 WebP → 原始 PNG → 英雄头像回退；未知英雄显示留空占位，不编造英雄或数据。

重新生成时使用已有的 Sharp 安装，不自动修改依赖：

```powershell
node scripts/buildHeroWebAssets.mjs --sharp-root '<已有的 sharp 包目录>'
```

生成脚本同时写入 `src/generated/heroArtworkAssets.json`，并检查原始图尺寸及透明通道。
