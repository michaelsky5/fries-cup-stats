# 周赛首发检查 · 2026-09-10

目标：下周用于周赛。首发重点是邀请激活、参赛准备、队长操作、选手读取和赛果响应。首轮完成竞猜入口隐藏及阻塞操作的前端修复，后续补齐独立参赛赛事入口与导航；尚未部署，不能据此宣布正式周赛已具备上线条件。

设计依据：[品牌规范](fries-cup-design-system.md)和[赛事中心实施规范](fries-cup-data-signal-design-system.md)。账号操作采用 Control 模式，优先呈现当前状态、权限、期限、结果与恢复入口。

## 本轮修复

| 问题 | 现在的行为 |
| --- | --- |
| 竞猜分散在空间导航、观众引导和快捷入口 | 隐藏这些入口；旧 `section=predictions` 链接回到概览并保留赛事、语言等参数。保留未挂载的功能实现与服务端契约。 |
| 部分账号请求可能一直停留在处理中 | 账号请求默认 15 秒超时，覆盖响应正文读取；读取失败可重试，写入超时明确提示结果未确认，不自动重发。 |
| 参赛权限检查失败后没有页面内恢复动作 | 提供“重新检查参赛权限”；保留关注、账号设置和公开赛事入口。错误信息、标题及手机按钮重新整理。 |
| 登录后的参赛页被公开快照加载或失败阻塞 | 概览、待办、队伍、比赛等账号操作独立读取账号 API。关注、个人数据和公开页面仍保留快照加载边界；概览不会把尚未加载的关注资料显示为空关注。 |
| 无下一场比赛时，“查看我的比赛”可能进入队伍页 | 按可见栏目生成对应目的地和文案，比赛入口优先进入我的比赛。 |

## 当前上线阻塞与下一步

### 1. 正式周赛入口代码已补齐，本地正式构建已验证

后续本轮已移除账号参赛入口对公开 `SEASONS` 和开发参数 `platformSeason` 的依赖。邀请使用独立的 `competition` 参数；System 的 `/me/identities` 返回当前账号有效队伍关系对应的赛事名称、状态及本人角色，参赛内容仍经过服务端开放策略与权限检查。

只有一项关联赛事时自动进入，多项赛事时明确选择；已进入的赛事按账号在当前浏览器会话中记忆。邀请、设置分区、刷新、空间返回及全站个人入口保留参赛赛事。切换赛事时清理旧周期、队伍、周次、比赛与任务筛选。无关联、旧链接、读取失败与邮箱未验证有各自恢复入口。

公开档案继续使用 `season`，公开页面链接不会带入参赛赛事；未发布公开档案的选手可以查看周赛准备与比赛，但不会被导向旧赛事的个人数据。归档赛事展示记录说明，不再预告下一场比赛。

本项需要 Stats 与 System 的对应代码一起发布；本次没有新增数据库迁移。实际生产周赛的配置及投递验收仍见下一项。

### 2. 正式配置和完整首发演练待验收

本轮没有读取或修改生产账号、白名单、邮件配置或周赛数据。发布前还需核对实际周赛的开放策略、队伍负责人关系、选手只读、确认截止时间、名单锁定规则，以及邀请与密码找回邮件的真实投递。以当前 System 发布说明为基准检查数据库与 API 版本、备份及回滚方案。

首发建议只开放已经验收的账号与周赛能力。竞猜保持隐藏，邀请制保持既定方向；其余新内容排在这条完整流程之后。

## 后续入口补齐与设计收敛 · 2026-09-10

验证结果：

- Stats 账号完整检查、选手无公开档案时的栏目回归检查、修改文件 ESLint、Vite 正式构建通过。产物输出到工作区外；最终构建 11.14 秒。
