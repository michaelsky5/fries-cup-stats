## 本轮行为

- System 接受并保留 RR5 格式。新建周赛配对默认为 RR5；已有方案缺少格式时仍沿用旧兼容值，避免自动更改历史比赛。
- RR5 必须完成五张地图，即使 3:0 也继续；平局占一图、不增加任一方胜场。第五图后不创建第六图。
- 五图总比分为 2:2 或五图全平为 0:0 时，正常进入战报、审核、双方确认和积分结算。未填写小分不会被当作真实 0:0；五图全平来自五张有效平局地图。
- 上图平局时保留原选择方，在下一张未用地图上重新选禁；上图非平局则败方选择。地图与类型限制、指定代表权限、版本冲突及事务内权限复核继续保留。
- 记分弹窗说明本图结果对剩余图数、下图选择方的影响；末图明确提示整场战报。过图区域显示已完成图数及具体操作代表；完赛区域展示五图完成、平局数和审核进度。
- 战报页按五图校验，平局保留五张地图及 Ban，不再因大比分相加小于五而遗漏平局图。赛管工作台与服务端共享格式和完成判定。
- Prisma 新增 RR5 枚举，迁移为 `20260913_rr5_match_format`。尚未在正式数据库执行。

## 规则书依据与执行口径

读取官网仓库 `docs/design-lab/homeground/events/weekly/assets/weekly-rules-v1.6.1.docx`：

- §3.2：RR5 强制打满五场。
- §3.1：正常小局胜 2 分、负 1 分、平 1 分；本队弃权小局 0 分、对方弃权小局 1 分。
- §7.3：中途弃权按全场弃权计算，弃权队伍当周积分为 0。

小局弃权的 0／1 分已经写在第 3.1 条，中途全场弃权方当周 0 分已经写在第 7.3 条。此前需要确认的是对手已得积分如何保留和合并；赛事方确认保留已得积分，剩余每张未完成地图按现有的对方弃权标准计 1 分，同时保留已打实际比分。该分支的本地实现与验证见 [弃权流程联调记录](weekly-room-rr5-forfeit-integration-20260913.md)，计算示例见 [规则执行说明](weekly-room-rr5-forfeit-supplement-20260913.md)。不新增弃权分值，也不将另行公布补充条款作为发布前置条件。

- 双方代表与赛管使用独立本机域名及真实登录 Cookie。
- 浏览器操作第一图：开启、双方出手、选图、Ban、准备、开赛、记分；对手提交前看不到已锁定出手。
- 中间第 2～4 图由真实 API 推进；浏览器检查第三图平局显示 `3/5`、`1 平`、BANANA 原代表继续选择。
- 第五图结果在浏览器提交，确认 `5/5`、2:2 整场平局、五图表格、战报交接。打开实际 System 战报页，确认五图、全部 Ban、双方比分与真实资料缺口。
- 桌面 1280px 无页面横向溢出；顶部同步、账号控件均 132×40。390×844 同源 iframe 加载实际房间，页面宽 390px、scrollWidth 382px，两个工具控件均高 44px；平局地图详情可读，Esc 后焦点回到原地图按钮。
- IAB 的 viewport override 未改变当前页面实际尺寸，因此窄屏使用同源定宽 iframe 并读取内部窗口尺寸验证，未将无效 override 当成手机证据。

此为浏览器关键步骤加 API 完整流程验证，不是五图及全部战报字段均在浏览器人工输入的验收。
