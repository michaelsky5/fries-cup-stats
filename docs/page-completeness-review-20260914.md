# 页面完成度复核与下一批建议

日期：2026-09-14

性质：当前工作区的只读 UI 与入口审阅。本轮未修改产品源码、评分或数据模型，未部署。以下区分已确认的操作断点、体验内容缺口和可继续精修的页面；不把没有回顾内容或没有公开数据自动视作程序错误。

## 建议优先级

| 优先级 | 页面或流程 | 当前缺口 | 建议完成的行为 |
| --- | --- | --- | --- |
| P1：操作断点 | 解说工作台、赛管身份空间 → 本届身份 | 「前往账号中心申请」进入账号设置，但那里没有本届职员申请；读取关系失败后也会显示「尚未申请」 | 依据真实邀请与身份机制提供正确下一步；分别表达读取中、失败、确认无关系、已存在关系。未开放公开申请时不要承诺可申请 |
| P1：公开浏览断点 | 全高杯赛事职员的具体比赛记录 | 可以看到署名场数、阶段和涉及队伍，但没有继续查看具体比赛的入口；底部停在「本届赛季回顾尚未发布」 | 在不依赖赛季回顾的情况下查看已发布的署名比赛，并能返回原目录与筛选 |
| P2：个人内容未形成完整入口 | 经理、教练，以及赛管、解说的通用个人档案 | 当前经理、教练预览只有身份与队伍摘要，继续入口前往队伍。赛事职员则借用赛季回顾承载详情 | 形成通用职员档案：经理／教练表达本届身份和所属队伍；赛管／解说表达实际署名、阶段与协作记录。已有回顾作为补充入口，不能把队伍成绩推导成个人执教成绩 |
| P2：手机阅读顺序尚需重排 | 阵容总览、队伍展厅 | 首屏仍主要用于大标题与展示图，查找或具体人物较晚出现 | 阵容优先查找和队伍选择，统计收紧；队伍优先身份、最终结果和成员入口，再展开完整展厅 |
| P3：分享体验尚未统一 | 队伍分享图与弹窗 | 手机可完整缩略预览，但无法放大核对；卡面仍使用 DATA CENTER、STATS.FRIES-CUP.COM，弹窗控制与新选手分享不同 | 沿用选手分享的完整预览、大图查看、明确反馈；按命名规范统一中文标识，英文名称和域名仍以正式命名决定为准 |

公开职员档案是下一批 UI 中最值得补全的一组。身份入口断点应优先修复；随后做职员档案，再集中处理阵容与队伍的手机顺序。此建议不要求继续扩充已经完成的选手详情。

## 当前浏览器证据

公开页面使用 `http://127.0.0.1:3026`，账号使用单独启动的本机合成审阅服务 `http://127.0.0.3:3047`。后者不转发真实账号、邮件或赛事写入。

### 职员公开页面

- FCR2026 `/staff?group=event`：Maverick 有 27 场解说署名、3 个阶段、26 支涉及队伍。继续入口进入 `/review/story/staff/caster/Maverick`，实际加载 13 个故事章节，其中包括协作对象和比赛回看。因此不能说常规赛职员完全没有详情。
- QGCS4 同一目录：牛萨库斯有 13 场赛管署名，小组赛 6 场、季后赛 7 场；预览底部仅显示「本届赛季回顾尚未发布」。目录和预览中没有具体比赛链接。这是数据已有而阅读路径未接完整的例子。
- FCR2026 `/staff?group=team`，手机打开 Dani2ois：显示经理身份、BattleTag、AIP 与全季 6 位选手，主要入口为「走进队伍档案」。没有独立职员个人记录入口。
- 当前路由只提供职员目录和 `/review/story/staff/:staffType/:staffKey`，没有通用职员详情路由。实现对应 `src/features/staff-credits/StaffCredits.jsx` 的 `CreditFolio` 和 `getHref`。

### 职员工作台与账号

- 在合成解说工作台实际点击「前往账号中心申请」，落点为 `/account`。实际页面分区只有账号概览、个人资料、修改密码、邮箱验证、登录设备，没有页面承诺的解说申请。
- 职员关系接口未被当前合成服务覆盖时，页面同时显示「尚未申请」与「本地设计预览未模拟此操作」。源码 `EventStaffControl.jsx` 也确认失败只设置错误，空 `context` 仍进入未申请分支。这证明错误回退表达有问题，不证明正式接口本身不可用。
- 赛管、解说共用上述关系组件。已抽查两种入口，未提交邀请确认、退出、档期或报名。
- 账号设置实际展示五个完整分区；任务中心实际展示首要任务、其他待办、截止与处理入口；赛事消息展示流程消息、公告、申诉和任务入口。通用报名可以加载草稿、成员邀请与审核入口。上述页面不应因为职员入口问题被整体判为未实现。
- 账号审阅是组件与导航检查，不代替真实服务写入或真实工作人员的周赛验收。最新真实账号测试进展另见 `account-joint-acceptance-20260913.md`，本轮未重新执行。

### 手机与分享

实际手机尺寸为 390 × 844；数据位置是当前样本的页面纵向位置，不是所有队伍的固定值。

| 样本 | 观察 |
| --- | --- |
| FCR2026 阵容总览 | 大标题约 237px，搜索约 590px，首支队伍详情标题约 928px；首屏主要是介绍和四项统计 |
| AIP 队伍展厅 | 队伍名称约 229px，人物章节约 1196px，当前选手姓名约 1781px；手机仍先完整堆叠封面构图 |
| AIP 队伍分享 | 实际卡面约 327 × 184px，可完整预览；现有操作只有关闭、调整英雄、自动去重和导出，没有放大查看。未在本轮导出 PNG |

上述页面没有外层横向溢出，问题在内容顺序与小字可读性。桌面阵容、职员预览和队伍分享均已结合截图查看，不能把叙事展厅允许的留白直接认定为缺少功能。

## 其余入口检查

当前路由清单已核对，`/schedule`、`/following`、`/standings` 属于有意保留的重定向，不是尚未完成的独立页面。

FCR2026 手机入口抽查覆盖 `/players`、`/teams`、`/leaderboard`、`/heroes`、`/maps`、`/matches`、`/advance`、访客 `/me`，均加载对应栏目标题，检查时没有可见错误提示或外层横向溢出。其中排行、英雄、地图、赛程和晋级已有各自内容分区。这只是入口与主要结构检查，不是每个筛选、详情、空状态的完整验收。

Fantasy、商店、生涯、冠军与私密 scouting 属于路由中的独立支线；本轮没有逐一操作其内部流程，也没有据此认定它们未完成。没有重新检查周赛的每个阶段、所有回顾章节、全部赛事和所有登录角色。

本轮只新增此审阅记录。测试用页面与尺寸覆盖在结束前清理，保留原有选手预览。
