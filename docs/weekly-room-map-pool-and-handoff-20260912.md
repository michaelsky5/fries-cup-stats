## 参赛者与赛管的路径

1. 比赛房记录各图地图、Ban 和比分，达到整场获胜条件后显示赛后进度。
2. 本场赛管或管理员生成战报入口。战报预填地图、顺序、Ban 和比分，再补充截图、回放、时长和选手数据，提供返回比赛房入口。
3. 已有房间选禁记录的战报固定地图与 Ban 来源。前端禁用相关编辑；提交和审核事务再次核对，不能通过战报改成池外地图、其他池内地图、另一手 Ban 或关闭 Ban。
4. 战报提交后等待管理员审核；退回则等待更正。管理员批准后，才可开放双方正式赛果确认。
5. 两队队长／经理确认或提出异议。对方和解说看状态，本队与赛管能看核对说明；响应带版本检查。
6. 双方确认且申诉等待期结束后，管理员填写积分和结算依据。积分不会从比分自动猜测；不计积分的周期双方记 0 分。
7. 房间显示双方结算积分，保留沟通与地图记录。公开积分榜仍以管理员发布的版本为准。

交接链接只返回给有本场权限的工作人员，不进入公开沟通。写入重新核对会话、职责、赛事状态、版本及编辑占用；重试使用提交编号。战报进入审核后禁止直接在房间覆盖赛中比分。

修复战报批准后立即误报“需要重新复核”：审核签名基于写入后的规范化记录生成。之后真实修改选手数据仍使审核失效；已有积分流水也不会让房间继续误显示“已结算”。

## 查看与继续

[本机各阶段入口](http://127.0.0.1:3054/local-opening-check) 现提供 13 个场景入口，包含三种首图方式、赛前设置与同顺位恢复；点击后使用该阶段对应的合成账号登录，无需复制账号密码。也可从经理、队长、赛管、解说、管理员视角进入同一场开局演练。房间顶部的深灰演练导航可返回全部阶段，或以另一身份重新进入当前比赛。

此前入口直接链接到受登录保护的比赛房，另一个浏览器或会话失效后只能看到登录页。现在独立的本机 Vite 中间件通过真实本机账号接口取得 HttpOnly 会话，再进入房间。入口只接受指定本机来源、固定合成账号和演练场景；不改产品登录、后端权限或正式构建。跨演练地址跳转保留正常的 SameSite=Strict Cookie 行为；密码不输出到索引页。

入口补验：五种身份均从无 Cookie 的 401 开始，经真实登录后读取账号和房间 API 得到 200；外站来源、错误身份地址和非演练目标拒绝。浏览器实际复现未登录页后，通过索引进入完整解说房间，并验证经理选图、Ban、赛管更正、第二轮类型、战报交接、正式响应、已结算与开局入口。房内切换经理到赛管保持同一比赛编号。

M1 保留可继续操作的真实本机开局流程；M2/M3/M5/M7 是明确标注的界面场景；M6 保留待双方确认；M9 已由浏览器完成确认和结算。可操作场景会保存进度，以房间实际显示为准。

发布时需要配置 Stats 的 `VITE_SYSTEM_APP_URL` 与 System 的 `ACCOUNT_PUBLIC_BASE_URL`。现阶段没有执行正式数据库迁移、部署、公开积分发布或真实赛事验收；上线前仍需按真实周赛配置、真实截图与实际工作人员完整彩排。
