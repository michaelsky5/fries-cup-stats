# 比赛详情 · 按比赛进程组织

日期：2026-09-13。范围为赛事中心 FC Signal 比赛详情的本地 UI 实现；未发布到线上。

## 设计

沿用纸色、墨色、黄色、直角控件和既有比分轴。状态改变信息重点，不额外引入装饰性 Hero 动画。

| 状态 | 首屏与阅读路径 |
| --- | --- |
| 待赛 | 双方对阵、公布时间、RR5 五局位置 → 比赛安排、直播和参赛入口。没有地图记录时不显示空战报。 |
| 进行中 | 当前比分、五局进程 → 已公布直播与赛管／解说 → 逐图记录。有记录的格子可跳转，没有记录的格子保持静态。 |
| 赛后 | 保留比分走势、MVP、地图战报、全场统计、选手比较和录像。 |
| 待审核 | 比分明确标记为待审核；保留已公布地图，暂不展示全场总结与 MVP。 |
| 延期／取消／状态未知 | 明确说明当前状态；延期时间标注“原定”。取消和未知状态不提供观看直播动作，不推断开赛。 |
| 弃权／裁决 | 保持既有独立结果说明，不补造正常比赛或统计。 |

五局进程中的比分是各局结束后的大比分，标题旁明确口径。桌面五列，手机在该组件内横向滑动；未公布地图不会把整个页面撑宽。

比赛安排采用直播与参与入口两栏，手机依次阅读。只有公开快照提供直播地址和工作人员时才显示对应内容；无信息时用简短说明。双方登记名单在有名单时折叠展示，明确区分登记与实际出场。

进行中地图缺少选手统计时，保留已公布赛果和一行说明。没有出场名单或禁用信息时不重复显示两块空阵容；有实际禁用或出场数据时仍保留。赛后地图的既有呈现不受此规则影响。

## 数据与导航约束

- RR5 无论比分都打满五局。3:0 不等于已结束，已录入五局也不能替代明确的结束状态。
- 只对明确标记为 LIVE／IN_PROGRESS 的地图显示本局进行中；不把第一个空位当作正在比赛。
- 即时比分不换算成周期积分。周期链接继续读取已发布的周期榜。
- 时间统一使用 UTC+8。缺失时间、只有日期或用于排序的合成时间，明确标注待定；不根据时间自动启动倒计时或更新比赛状态。
- 直播地址采用现有公开广播模型，只允许 HTTP(S) 入口；录像与赛事录像库不能伪装为观看直播。
- 周期、周次入口必须同时匹配公开周期、公开周次及其比赛列表，不能从相邻周期推断。
- 继续支持地图深链、章节定位、来处返回和原版设计。对阵里公开提供的队徽地址传递到首屏，失败时沿用现有回退。
