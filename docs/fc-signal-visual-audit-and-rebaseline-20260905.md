# FC Signal 视觉复核与实施顺序修订

日期：2026-09-05。依据：用户本轮反馈、当前本地页面、路由与组件结构，以及 [FC Signal 设计合同](fries-cup-data-signal-design-system.md)。

**结论：赛事总览与晋级形势保留主方向；赛程赛果精修；参赛阵容作为一个完整页面家族升级；比赛详情、队伍详情、英雄及地图需要重新组织整页。选手档案和排行已有实质新版结构，保留其有效部分继续深化。**

本轮仅检查与修订文档，没有修改页面代码。此前第二批完成的是功能、数据表达和响应式修复，不能据此认定视觉迁移完成。用户认为某页比较 okay，也不等于该页已完成正式上线验收。

## 视觉基准

仍沿用 FC Signal：KPR 的章节与场景组织、Marathon 的对比和信号表达、终末地的网格秩序、FryDeck 的转播信息层级，以及薯条杯自身的黄黑白品牌。

当前总览与晋级页值得延续的部分是：明确的主角、贯穿内容的网格、能解释数据关系的章节和路径，以及克制的重点色。后续页面应按用户任务使用这些规则：查找页面先给筛选和结果，人物档案先给身份和表现，账户页面先给待办与操作。

## 逐页判断

| --- | --- | --- | --- |

| 晋级形势 `/advance` | 保留主方向 | 选队路径、签表关系、明确的决赛终点 | 各阶段、单败/双败、待定和已完成状态仍须回归；保留必要的内部签表滚动 |
| 赛程精选 `/matches` | 精修 | 精选赛事、关键战与完整档案的双入口 | 总决赛在首屏和下一章节重复抢占焦点；标题与章节留白过大；浅底黄色小字对比偏弱 |
| 完整赛程 `/matches?view=list` | 精修 | 阶段、轮次、搜索和完整比赛索引 | 压缩标题、重复计数和筛选占用，让实际记录更早出现；提高行、轮次与状态的区分度 |

| 职员目录 `/staff` | 升级 | 职责分组、身份记录及关联队伍 | 子导航位置应与队伍/选手目录一致；收紧首屏统计和第二个大标题，尽早出现职员记录 |
| 队伍详情 `/teams/:teamId` | 整页重做 | 队伍身份、阵容、战绩、赛程、已有分享与数据逻辑 | 从队伍身份进入赛季结论、阵容与比赛；整合重复的“出场核心/完整名单”；降低地图背景对阵容的挤占；分享图跟随最终设计 |

| 数据排行 `/leaderboard` | 深化升级 | 紧凑索引、右侧人物档案、排序与同职责比较 | 统一数据页导航、指标/样本解释；提高小字和手机比较操作的可读性；保留主表结构 |
| 英雄数据 `/heroes` | 整页重做 | 真实英雄时长、阵容记录和相关选手数据 | 改为可查找和比较的数据索引；整合大摘要与重复卡片；职责/地图名称本地化；归档内容避免使用含混的“当前版本”表述 |
| 地图列表与详情 `/maps*` | 整页重做 | 地图素材、模式分组、全局/模式内占比、比赛及英雄关联 | 统一地图索引和情报详情；减少四格摘要、重复标题与重复统计；让查地图、看模式和进入比赛形成连贯路径 |
| 我的空间 `/me` | 重做 Control 布局 | 已有身份、关注、任务、报名和队伍业务模块 | 访客入口收紧空状态；登录后围绕身份、今日任务、下一场和异常安排操作，收敛多层标题与导航 |
| 比赛房 `/matches/:matchId/room` | 单列 Control 设计与真实验收 | 已有房间业务与服务失败恢复入口 | 本轮仅进入账户服务不可用状态，不能判断完整房间的视觉完成度；后续与我的空间共用任务、状态和操作规则，再按真实角色验收 |
| 回顾、球探报告、电竞经理 | 保留独立体验，精修衔接 | 放映、报告阅读和游戏各自的组织方式 | 抽查入口标题换行、语言、返回与赛季上下文；内部页面另行专项验收，不纳入公共数据页的整页重做清单 |
| 进行中赛事首页 | 待建设与验证 | 既有赛事与状态数据逻辑 | 使用以即时比赛和任务为主的 Index 布局；本轮实际公共赛事均已归档，不能用归档首页或固定预览代替进行中验收 |

## 可复现的视觉问题

| 编号 | 当前证据 | 设计处理要求 |
| --- | --- | --- |
| VIS-01 | FCR26 完整赛程在 1440×1000 下，第一个轮次标题位于文档约 y=1017；390×844 下约 y=1442，实际比赛行还在其后 | 合并页面介绍与结果摘要，收紧筛选层级；常规加载完成状态下，首屏出现实际记录或明确的空结果 |
| VIS-02 | 选手目录在 1440px 的 FCR26 和 QGCS4 都将“全部/重装/输出/支援/我的关注”挤压成竖排 | 以完整中文标签的最小宽度分配筛选区；窄屏采用清晰的换行或可辨认的横向滚动 |
| VIS-03 | 390px 阵容门户页签出现“阵容…”“参…”；选手页当前页签落在横向滚动区外；英雄/地图导航显示“选”“英…”“地…” | 优先完整显示中文入口，移动端减弱或移除重复英文；当前项可见；入口之间能明确区分 |
| VIS-04 | 职员目录先展示大标题和多组统计，之后才是阵容子导航；队伍/选手目录把子导航放在顶部 | 页面家族固定导航顺序、筛选位置和返回规则 |
| VIS-05 | 390px 选手目录把大幅人物预览排在名单前；选手详情的姓名约 y=780 才出现 | 目录以查找结果为先；详情首屏明确姓名、队伍和职责，人物美术围绕身份组织 |
| VIS-06 | AIP 队伍详情中，五名“出场核心”后紧接含同批人物的“完整名单”；地图场景先于阵容大幅展示 | 用一份完整阵容表达出场、核心和替补关系；地图作为队伍表现证据，降低重复铺陈 |
| VIS-07 | 比赛详情分析区同时使用镜像大表、黄色人物卡、三色职责行、下方多组摘要；地图轨道又在滚动时吸顶 | 重新分配比赛结论、比较与逐图阅读的优先级，统一行列和状态表达，并验证多个吸顶层的空间关系 |
| VIS-08 | 390px 排行页实际计算样式：数据子导航 8px、指标模式 9px、多个表头 8px，“条正式排名”7px | 导航、样本、职责和指标属于阅读内容，需要提高到可读尺寸；不要按装饰标签处理 |
| VIS-09 | 手机英雄页 50 张卡片单列延伸，文档约 16612px；地图页约 9949px，热门项与分组项重复 | 用紧凑索引、筛选/排序和按需展开详情控制浏览成本；页面变长应带来新的信息 |
| VIS-10 | 访客我的空间用大块区域表达“尚未设置关注”“当前轮暂无比赛”；经理固定预览有身份标题、主导航、队伍标题、队伍子导航多层堆叠 | 用紧凑的入门状态与明确的下一步；工作台让当前任务和主操作更早出现 |

上述坐标是当前数据、视口和加载状态的观测值，数据警告条、字体和内容变化可能改变位置。浅底文字对比问题来自实际画面判断；本轮没有进行全站逐色对比度测量。

实现层也能解释当前断层：比赛详情由 `matchDetailStyles.js` 合并旧样式与 `MatchSignal.module.css`；队伍详情由 `teamDetailStyles.js` 合并原版、FD 预览与 Signal 样式。此前的改动主要落在现有结构上。下一轮需要直接调整组件布局和内容顺序，再复用可靠的数据逻辑。

## 下一步实施顺序

| 顺序 | 一次交付的完整路线 | 具体结果 | 视觉验收重点 |
| --- | --- | --- | --- |
| A. 赛程路线 | 赛程精选 → 完整列表 → 比赛详情 → 返回原筛选 | 精修精选和列表；重做比赛详情主体；建立后续数据页可复用的页头、筛选、比赛行、状态与统计表达 | 先核对桌面和手机的首屏、分析区、地图区；实际点击选图与返回；保留已完成的缺数据和特殊赛果处理 |
| B. 阵容路线 | 阵容门户 → 队伍/选手/职员目录 → 队伍/选手档案 → 比赛/分享 | 统一四个目录；重做队伍详情；深化选手详情；同步分享预览和实际图片 | 目录到档案风格连续；姓名/职责可读；完整名单无重复；手机先可查找，档案先可识别身份 |
| C. 数据路线 | 排行 → 同职责比较/选手 → 英雄 → 地图详情 → 比赛 | 深化排行；重做英雄和地图；统一数据导航、过滤范围和样本说明 | 数字和分母清楚，筛选与结果接近；手机能读关键指标；比较与返回保留上下文 |
| D. 进行中赛事 | 即时总览 → 赛程/晋级 → 队伍/比赛 | 建立进行中首页，补齐未开始、进行中、完成、延迟及特殊结果 | 使用专门测试赛事验证同一状态在各页同步；归档赛事保留其叙事和最终结果 |
| E. 账户路线 | 登录 → 我的空间 → 报名/队伍 → 比赛房 → 结果与通知 | 完成 Control 视觉结构与真实角色联调 | 浏览器操作、API、持久化和其他角色读取均有证据；房间与身份状态可恢复 |
| F. 正式替换 | 独立体验衔接 → 双语/响应式/键盘/资源 → 预发布与回退 | 完整专项验收后切换默认新版，处理旧 URL 与分享链接 | 正常入口无需预览参数；生产资源、公共数据与真实账户流程可用 |

账户测试环境的恢复准备可提前开展；具体的视觉实施仍按完整路线推进。当前不新增缺乏依据的上线日期。

**下一次优先做 A：先给出能够运行的赛程列表与比赛详情，再用实际页面对照总览/晋级的品质，确认一条路线的视觉完成度。** B、C 随后沿用已验收的公共组件，避免每页各自发明一套页头、导航和卡片。

## 完成条件的修订

每条路线分别记录“视觉”“交互与数据”“真实业务”状态；只有适用层次都通过，才记为该路线完成。

1. 视觉查看整页的首屏、中段、底部和关键状态；对照已认可页面的主次、网格、信息顺序与滚动节奏。
2. 数据索引页正常首屏出现结果；身份页正常首屏出现身份；操作页正常首屏出现当前任务或明确下一步。
3. 实施后检查 1440、980、390px；公共页头额外检查 1280px，复杂签表额外检查 2048px。正式切换前再补齐设计合同要求的 1024、320px 和全站矩阵。每个宽度都重新组织内容，不只缩小字号。
4. 正文以 14px 及以上为目标，重要辅助信息至少 11px；检验长中文名称、英文标签、空状态和色彩对比；当前导航不被截断到无法辨认。
5. 检查真实图片加载、选择/比较/返回状态，分享页还要打开导出的 PNG/PDF。必要内部滚动与文档意外横向溢出分别记录。
6. 保留前两批已经完成的导航、数据真实性、归档措辞和精确队伍检索修复。按实际改动做必要逻辑回归，构建和测试不作为视觉验收的替代证据。
7. 上线前覆盖归档赛事、专用进行中赛事及真实账户角色；固定假数据预览只证明相应组件画面。

- 浏览器：本地 `http://127.0.0.1:3026`，公共页使用 `design=kpr5`；FCR26 为主，QGCS4 补查选手目录。查看了总览、晋级、精选/完整赛程、比赛详情、阵容四个入口、队伍/选手详情、排行、英雄、地图/详情、我的空间、比赛房错误状态、经理固定预览、回顾入口、球探本地预览和电竞经理入口。

- 本轮没有修改页面代码，没有运行构建或测试，没有提交、推送或部署。旧文档副本与视口记录位于 [检查产物目录](../artifacts/fc-signal-visual-rebaseline-20260905/browser-observations.md)。
