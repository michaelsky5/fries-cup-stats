# 我的空间与我的关注 · 交互收敛

日期：2026-09-11。范围为本地实现及验证，未提交、推送或部署。

依据：`fries-cup-design-system.md` 1.1、`fries-cup-data-signal-design-system.md` 2.1（2026-09-10）。延续现有全局导航；工作区突出当前动作，阅读与历史使用纸色。

## 本轮变化

- 首页突出一项优先待办，显示具体动作、处理身份及截止时间；其余事项收为简短列表。与任务中心共用已经解析的流程地址。手机把主操作安排在说明之前。
- 手动事项通过 `section=tasks&task=…` 打开自身详情；从任务中心直接完成也进入对应回执。重新读取后在同一地址显示已完成记录及下一步，失效地址提供恢复入口。完成回执必须确认返回的任务 ID、状态及存在的账号/赛事范围一致。
- 首页参赛进度先展示当前事项摘要；历史单独进入。选择事项再展开完整阶段、权限、处理人和后续入口。任务中心保留参赛进度入口，避免再次完整铺开同一套内容。进度筛选、指定事项、展开与收起保持 URL、焦点及返回行为。
- 周赛保存反馈放到实际操作区，保存后定位到回执。确认参赛后可直接继续填写同一队伍、同一周次的名单；草稿、已提交、等待管理员分别显示。继续编辑产生新草稿时隐藏旧回执，避免误以为新修改已经保存。
- “继续出赛名单”最初把锚点拼入步骤参数，浏览器连续操作发现后已修复，并加入回归检查。赛事、语言、队伍和周次继续保留，旧任务筛选不会带入新步骤。
- 关注近况优先呈现正在进行/接下来的比赛及最近赛果；归档赛事只以历史赛果作为焦点。辅以最多两场关联比赛，空的更新提示收成一行。队标使用浅色衬底保证辨识度；比赛正文、状态、比分仍来自原有关注数据模型。
- 有关注时弱化“发现关注”按钮；完成选择后将焦点交还关注近况。维持本机保存/账号同步、赛季范围与比赛详情返回状态的原有边界。

## 验证

用户路径：空间待办 → 对应周次表单 → 保存/提交 API → 重新读取 → 原位回执 → 本次进度及更新后的队列。

- `npm run test:account-ui` 通过。后续定位修复及细节调整运行了相关准备、空间、关注、任务回归与 ESLint。
- 新增模型检查覆盖指定手动任务、错误完成回执、解析后的任务地址、当前/历史摘要、失效进度链接、步骤锚点与上下文，以及关注焦点的实时/未来/归档/无赛程选择。
- Vite 生产构建通过；构建输出在工作区外。`git diff --check` 通过。另检查本轮新增/原未跟踪文件的变更行空白。
- 浏览器：1280px 中文空间、390px 中文空间和周赛表单、980px 英文关注、390px 中英文关注。检查的外层文档宽度未超出视口。
- 从首页提交样例名单：保存接口返回后重新读取，名单为 `SUBMITTED`；回到对应周次，显示等待管理员锁定，待办由 2 项减为 1 项。
- 从待确认参赛开始：确认参赛 → 继续出赛名单，定位为 `weekly-roster`，URL 的 `step=roster` 与 `#weekly-roster` 正确分离；5 人名单保存为草稿后仍可提交，正式提交后显示等待管理员的回执。
- 手动任务分别从首页详情、完整队列完成；服务端样例记录为 `COMPLETED`，同一详情刷新后仍为已完成，并给出剩余待办入口。未知任务地址没有打开其他任务。
- 选手样例只显示等待队长/经理的进度，没有派发本人的名单或赛果提交待办。取消的周次进入历史视图，刷新保留筛选。
- 游客添加 BANANA 关注，刷新及语言切换后保留本机关注；从焦点比赛进入详情，通过页面返回按钮回到关注页，语言、赛事和浏览位置保留。
