# 薯条杯赛事中心 · FC Signal 设计与实现规范

版本：2.5.42

日期：2026-09-26（周赛总览布局精修）

上层规范：[《薯条杯设计系统 · FC Signal》](fries-cup-design-system.md)。品牌核心、官网与赛事中心的分工、共同视觉语言及跨产品评审以主文档为准；本文承载赛事中心的具体实现要求。

公开页面的加载失败与不存在状态使用 EVENT CENTER 品牌、当前语言、直角操作和本赛事返回入口。公告时间轴只表达计划日期，不以日期已过推断比赛已完成。备份快照必须标明来源与可能过时；更新失败保留已有记录，首次加载失败提供重试。回顾页面所需的语言资源必须在站内跳转和直接访问时都先于正文准备完成。固定候选、跨赛事入口和失败恢复的验收边界见[公开 UI 发布前验收记录](public-ui-acceptance-20260914.md)。

手机归档首页在 600px 及以下继续按「冠军 → 系列荣誉 → 赛事入口 → 冠军征程 → 人物 → 回顾」阅读，章节只随该赛事实际内容出现。首屏之后提供吸顶章节选择，选择后定位并聚焦标题；荣誉采用紧凑名录，图谱采用四个入口，冠军征程采用连续比赛记录。手机内容直接呈现，桌面保留群像、完整图谱和章节动效。首页进入比赛、选手、队伍及回顾时保留来源和阅读位置；回顾入口、正文、语言切换与退出继续传递首页来源。窄屏回顾将章节选择单独放在第二行，保留长文阅读空间。赛事标记从当前赛季读取，赛季菜单中包含轮空的数量称为“赛程记录”，与实际比赛数区分。实现与验证边界见[手机首页与回顾阅读精修记录](mobile-home-reading-refinement-20260914.md)。

手机「我的关注」在 700px 及以下按「关注比赛近况 → 队伍或选手 → 保存与同步」阅读。页头保留实际关注数量、添加和管理入口，名额上限留在管理界面；正常保存状态移到页尾，同步失败仍在页头直接提示。首次访问直接发现与搜索对象。近况保留一场重点比赛，其他关联比赛用紧凑横行呈现；周赛五局进程与未发布状态完整保留。队伍和选手在手机按类别切换，只有选手时默认显示选手目录，切换与比赛筛选各自保存在链接中。进入比赛或档案后返回保留来源与选择，从目录查看相关比赛时先完成视图切换，再定位并聚焦列表。桌面仍展示完整页头和两类目录。登记职责与实际出场分开表述。实现与本地验证见[手机我的关注精修记录](mobile-following-refinement-20260914.md)。

手机英雄与地图数据在 600px 及以下按「查找对象 → 识别对象 → 查看记录 → 回到具体比赛」重排。英雄索引的三个职责代表使用紧凑头像列；英雄档案以姓名、英雄图、记录出场率及三个记录入口组织首屏，随后直接显示使用选手。地图档案将地图身份与图像并排，保留赛季占比、有效时长样本和队伍规模；同模式比较与单图纪录按需展开，全部职责先呈现各职责出场最多的英雄，选择职责后浏览完整名单。两个索引将统计说明收进原有口径区域，入口随列表标题保留。桌面继续使用完整展示卡、并排分析及展开的数据比较。展开列表、记录页数和筛选随链接保留，切换英雄清除详情阅读状态；返回继续使用当前语言。具体实现、跨赛事浏览器检查和交付边界见[手机英雄与地图精修记录](mobile-data-refinement-20260914.md)。

手机晋级形势按「阶段 → 选队 → 队伍记录 → 完整赛场」阅读：紧凑页头与等宽阶段入口之后直接选队，瑞士轮先看所选队伍的逐轮记录，战绩分布按需展开；季后赛先看单队路径，完整签表保留内部横向滚动。全高杯小组赛在手机一次查看一个实际小组，学院赛突围赛沿用已发布轮次，不套用常规赛四分区。最终结果先呈现冠军身份和决赛比分，再阅读冠军路径及最终排名。桌面保留完整图示与并排索引。选择、区域和签表展开状态随链接保留，比赛返回沿用原来源与阅读位置；周赛继续区分正式积分、进行中比分与试运行记录。实现及本地浏览器验证见[手机晋级形势精修记录](mobile-advance-refinement-20260914.md)。

手机完整赛程收拢页头，队伍搜索就地清除；已选筛选在“更多筛选”展开时显示，不在列表前追加独立状态行。比赛战报按「比赛概况 → 选择地图 → 选手表现 → 按需查看完整指标」阅读。760px 及以下一次呈现一张实际地图，保留地图选择、前后图、回放代码和全场分析入口；桌面继续纵向阅读全部地图及双方完整表格。手机单图表现直接展示姓名、职责、英雄、本图评分、消灭/助攻/阵亡，以及重装阻挡、输出伤害、支援治疗；完整数据保留全部指标。切换场次重置地图条位置，返回保留原地图、数据视图与来源筛选。未发布统计、弃权和进行中仍遵循数据来源与状态边界。具体实现和三赛事、周赛样例检查见[手机赛程与战报精修记录](mobile-match-flow-refinement-20260914.md)。

手机阵容总览按「查找 → 选队 → 阵容 → 本届规模」组织内容；队徽先以可横向浏览的一行呈现，展开后选择队伍会收起列表并定位到阵容。队伍展厅先交代队名、队徽、全季人数与已公布名次，随后直接进入成员选择和记录，桌面保留封面与人物群像。手机人物卡以姓名和实际出场为主体，登记未出场成员不补英雄或统计。队伍分享提供完整缩略图、可滚动大图、Esc 逐层返回和生成后的再次保存入口。分享名单保留全季所有成员，仅限制英雄画面最多七位，其余实际出场与登记未出场成员分开署名。英文公共品牌与分享卡统一使用 EVENT CENTER；合作赛事不使用 OFFICIAL TEAM DOSSIER 标记。具体实现、三赛事检查与下载验证边界见[手机阵容与队伍精修记录](mobile-roster-team-refinement-20260914.md)。

职员目录与阵容总览中的姓名统一进入 `/staff/:staffId`，详情不依赖赛季回顾是否开放。赛事职员以本届职责、公开头像、实际署名场数及可筛选的比赛记录为主；战队职员以队伍登记、成员与同队职员为主，不把队伍战绩归为个人执教或管理成绩。不同职责和队伍登记各自保留标识，未知选手档案不生成虚构入口。手机先显示紧凑身份和关键规模，随后进入记录；返回保留原目录条件、阶段筛选与阅读位置，切换赛事回到该赛事目录。已归档赛程补充的署名必须说明来源。工作台明确区分同步中、读取失败、无本届关系、邀请、已生效及历史状态；失败保留已知记录并暂停变更，身份入口遵循当前邀请流程。实现及验证边界见[三赛事职员档案交付记录](staff-archives-20260914.md)。

选手档案的内容规模随实际记录调整：仅一场出场时保留代表比赛，省去重复的赛季片段；无公开出场时以登记身份和队伍入口为主，不展示三项零值或重复等待区。手机封面将姓名与紧凑英雄图并排，随后呈现荣誉、出场规模、英雄选择与操作；代表比赛的逐图记录按需展开。赛季分享继承封面所选的实际出场英雄及其职责，卡面明确区分最多出场、并列最多和主动选择；选择图像不改变数据范围。分享提供完整缩略图与可滚动大图，保持直角控件、键盘循环及 Esc 返回。实现与本次浏览器验证边界见[选手档案收尾精修记录](player-profile-finish-20260914.md)。

选手档案增加可回到比赛的「代表一战」，竞技分析先呈现有依据的个人数据解读，再进入指标与走势。选手可以分享自己的赛季、某一场比赛或某个实际出场英雄，并主动选择职责、比赛和英雄。代表比赛只在同职责已结束且已公布全场评分的比赛中比较；单场样本不称赛季最佳，并列按公开精度保留。低样本以出场事实为主，未出场选手保留登记身份卡，不推导荣誉或英雄评分。首版实现及当时的验证边界见[选手个人记录与分享设计](player-personal-story-20260913.md)，后续浏览器补验以上述收尾记录为准。

选手竞技分析以明确的职责范围组织数据。身份、赛季 OVR 与出场样本收拢到页头，表现、英雄、地图、比赛采用等宽入口；六项指标同时呈现个人值和同职责均值，近期比赛只作紧凑摘要并联动完整走势。英雄选择先于图像，手机逐图统计按地图纵向阅读，筛选不插入独立标签行。档案与征程的比分统一说明本队在前。此轮具体实现与验证边界见[选手三页精修记录](player-pages-refinement-20260913.md)，覆盖此前同模块的版式规则，不改变既有评分、出场和数据来源约束。

状态：长期实施基线；文档要求、页面实现、功能验证、视觉验收与正式发布分别记录。本文不把设计目标写成已完成状态。[2026-09-05 视觉复核](fc-signal-visual-audit-and-rebaseline-20260905.md)为当时的检查与计划，后续专题交付需按日期另行核对。

公开页面默认采用 FC Signal，不再要求访问链接包含 `design=kpr5`。显式设计参数继续作为旧书签与视觉对照的兼容入口；普通导航不自动添加该参数。设计工具条只在开发环境且主动指定 `designPreview=1` 时显示，生产构建始终隐藏，并同步移除工具条占用的吸顶偏移。构建变量 `VITE_DEFAULT_PUBLIC_DESIGN=original` 仅用于切回旧版默认视觉；完整生产回退仍依赖上一部署版本。当前实现、候选产物与未完成发布项见[公开 UI 发布候选记录](public-ui-release-candidate-20260913.md)。

手机按阅读任务重组信息。600px 及以下的新版公开页面采用紧凑顶部赛事栏与底部「总览 / 赛程 / 阵容 / 数据 / 更多」导航，保留纸色、墨色、黄色和直角控件。归档首页先呈现冠军、决赛、赛事入口与一位冠军人物，再继续原有赛季内容；首屏不启用桌面冠军舞台的滚动切幕与指针动效。选手排行先呈现职责、查找和选手记录，详细筛选、排序、数据口径与完整表格设置集中到下方抽屉；正式排名开关占据固定位置，不新增筛选标签行。桌面与平板保留原框架，旧版视觉和参赛任务空间保持各自入口。本轮仅完成上述第一批，阵容与详情等页面仍需继续重排，具体范围和验证见[手机 UI 方向与首版记录](mobile-ui-direction-20260913.md)。

归档首页由深色页尾统一承载版权、素材来源与数据更新时间，外层不再追加浅色更新时间栏或底部留白。手机固定导航所需空间放在深色页尾内部，保证状态文字可以完整滚出导航上方。已有赛季回顾主入口时，结尾只保留数据排行入口；未提供回顾的赛事保留赛果入口并使用对应文案。数据状态沿用通用来源与刷新状态，其他页面的状态栏不受此规则影响。

赛事切换按「官方赛事 / 合作赛事」分组，常规赛与学院赛归入官方赛事，全高杯归入合作赛事；分类与「进行中 / 已归档」及数据刷新状态分别表达。当前赛事身份在公共状态栏和归档首页中保持一致，合作赛事的叙事文案使用本届赛事的名称与身份。归档配置在快照尚未可用时提供生命周期依据，实际已发布比赛状态可覆盖它。未开放的赛季回顾保留当前赛事上下文并提供返回入口。共用设计语言不能强制共用赛制：学院赛突围页按已发布轮次呈现，不套用常规赛的四分区路线。范围、发现和本地验证边界见[跨赛事页面检查记录](season-pages-audit-20260913.md)。

周赛进行中首页采用 Index 模式：主对阵、RR5 五局进程、已发布周次和周期积分共用 FC Signal 纸色、墨色、黄色与直角控件。以 System 的公开周期快照为数据依据，赛季状态不能套用瑞士轮推断。具体设计、预览方式与当前边界见[周赛总览首版记录](weekly-overview-design-20260912.md)。

周赛赛程与总览共用周期选择和周次导航，按已发布周次、比赛日组织对阵。桌面行中呈现状态、时间、双方与五局记录，手机把地图记录移至比分下方；筛选不新增独立标签行。总览、赛程和详情保持周期、周次及返回位置。具体实现与检查见[周赛赛程首版记录](weekly-schedule-design-20260912.md)。

周赛晋级形势以周期积分榜和选队比赛历程为主体，用三等分路径连接周期积分、周期季后赛与 Weekly Major。沿用公布名次、并列和积分，不把实时比分换算为正式积分，不推断入围线；试运行周期保留对阵，不生成积分名次。具体设计与数据边界见[周赛晋级形势首版记录](weekly-advance-design-20260912.md)。

比赛详情根据待赛、进行中和赛后调整内容重点。待赛以对阵、时间与比赛安排为主；进行中展示当前比分、完整 RR5 五局位置和已公布地图，直播与人员信息跟在比分之后；赛后保留逐图战报、选手统计和录像。审核、延期、取消及裁决沿用独立状态，不能由比分或时间推断。具体边界见[比赛详情进程设计记录](match-phases-design-20260913.md)。

我的关注保留近况与关联比赛两个视图，沿用等分导航、墨色主对阵、纸色对象卡片和直角控件。周赛以公开周期整理比赛，队伍卡片读取已公布积分与并列名次；试运行不生成正式积分。进行中 RR5 保留五个地图位置，并与详情共用状态、比分口径及地图定位。选手头像取自已有常用英雄记录。具体交付与验证见[我的关注周赛设计记录](following-weekly-design-20260913.md)。

六个主页面的公共框架按统一规则收尾：周赛总览、晋级与公开关注入口共用紧凑赛事状态栏，数据来源、更新时刻、演示说明及重试集中呈现；周次与关注视图接入阵容、排行共用的分区导航样式。普通索引标题与紧凑数据标题分别使用固定字号档位，保留档案场景的主视觉。搜索、周期选择、直角控件及手机文字采用相同尺寸规则。具体范围和验证边界见[公共框架统一精修记录](public-ui-consistency-20260913.md)。

页面高度应由内容决定。周赛总览在桌面将焦点比赛、本周对阵和关注队伍连续放在主栏，周期积分独立放在侧栏；对阵列表紧随焦点，不等待积分榜结束。手机依次阅读焦点、对阵、积分和关注队伍。我的关注在焦点下方并排呈现紧凑摘要。选手图鉴按数量排布：一项使用横幅，两到三项使用同组展示卡，更多英雄使用主卡加列表；手机保留主卡与紧凑次项。选手档案、分析及队伍征程、分析复用紧凑状态栏和黄色整栏页签，地图样本筛选与正式排名筛选共用直角开关。赛季没有任何选手统计时，仅保留分区导航、状态说明和继续浏览入口；筛选后无结果仍提供恢复筛选。首页门槛说明必须复用评分资格口径，不另写固定分钟数。此前交付与浏览器检查见[公共 UI 升级记录](public-ui-upgrade-20260913.md)。

周赛报名入口采用紧凑纸灰工具条，报名与每周确认并列，参赛说明按需展开；640px 及以下默认折叠操作，已公布的确认窗口仍单独显示。焦点比赛以队徽、队名和比分组成横向记分牌，五局记录可使用现有地图素材；600px 及以下在卡片内横向浏览地图，页面本身不横向滚动。积分榜保留全部公布名次、并列与零值，未出赛行仅降低视觉强调，队名进入队伍档案。继续保留 RR5 固定五图、待赛使用 VS、实时比分不重算积分、试运行不生成排名的边界。

常规赛回顾入口采用「自己的档案 / 共同的赛事」双路径：纸色搜索区与墨色赛事入口并列，搜索结果在桌面通栏排列；手机搜索结果紧跟输入区，赛事入口随后。身份只是可选筛选，观众直接进入赛事回顾；不重复呈现自动识别、实时匹配和零结果提示。返回入口保留搜索词、身份与当前语言，分享章节不携带搜索条件。桌面章节索引展示标题与序号，长文保留独立滚动和原有内容。具体范围、检查与边界见[赛季回顾精修记录](review-entry-polish-20260913.md)。

选手分析的比赛走势与逐图战报分层排布：桌面上区并排放置按日期排列的曲线和最近在前的比赛列表，下区通栏呈现所选比赛及出场地图。地图数量不再撑高图表一侧；一至三图用紧凑横行，更多地图用等宽卡片。手机将比赛列表改为内部横向滑动，地图改为纵向记录。仅一场出场时直接展示单场表现；无记录保留明确回退，不补零或绘制虚构走势。全场评分与单图评分分别标明满分 10 分，继续使用既有评分和返回上下文。具体范围与验证见[选手分析精修记录](player-analysis-polish-20260913.md)。

选手详情分为「选手档案 / 赛季征程 / 竞技分析」三个连续入口，保留统一导航与赛事上下文。档案首先交代身份、队伍、已公布荣誉及出场规模，手机沿此顺序阅读；英雄图鉴先展示最多四位，其余使用可展开列表，单英雄使用横幅。并肩队友仅从同队同图的实际出场计算，赛季片段只提供可回到具体比赛的节点。独立征程按本赛事实际阶段组织个人出场，并保留逐图的各职责原始评分。无出场时不制造故事或重复空图表。手机分享卡按可用宽高完整缩放，导出画布保持 1600 × 900。具体实现与本地验证见[选手档案升级记录](player-archive-upgrade-20260913.md)；本段为选手档案的新基线，取代此前图鉴“更多英雄使用主卡加列表”的排布约定。

## 1. 设计定位

薯条杯赛事中心把比赛、参与者与连续记录组织在同一个赛事上下文中：既能呈现冠军、选手和赛季故事，也能快速处理赛程、晋级、阵容、排行及参赛任务。

中文对外名称为 **薯条杯赛事中心**，短称 **赛事中心**；长期内部设计语言名称为 **FC SIGNAL**。原有 `FRIES CUP DATA CENTER` / `DATA CENTER` 是待迁移的英文标识，英文更名与字标组合在命名交付中单独明确。`Data / Signal` 等早期稿名不进入正式用户界面。

FC Signal 是跨赛季长期使用的系统，不属于某一届赛事。导航、数据组件、状态语义、排版和无障碍规则构成约 80% 的固定基础；每届赛事可以在约 20% 的范围内调整 Hero 素材、章节氛围、辅助纹理和叙事文案，但不能改变状态含义、交互习惯和数据口径。

当前 URL 中的 `design=kpr5` 与代码中的 `data-design="kpr"` 只是预览兼容键，不作为用户可见品牌名称。正式迁移完成后使用 `signal` 作为代码语义，旧键只保留兼容映射。

设计依据优先采用已经形成的薯条杯页面关系：

| 主要依据 | 保留的设计品质 | 在赛事中心中的表达 |
| --- | --- | --- |
| 薯条杯官网 | 社区参与、海报表达、纸面档案与清晰邀请 | 人物身份、赛季故事和主要入口 |
| 新版赛事总览 | 冠军群像、人物镜头、赛季图谱 | 团队 → 人物 → 比赛与赛季记录 |
| 新版晋级形势 | 选队路径、阶段关系、排名与具体依据 | 当前对象、整体关系和逐场记录共同响应 |
| FryDeck overlay，次要参考 | 转播信息层级、即时状态、清晰数字 | 比分、状态区、重点数值与短促反馈 |

外部参考的历史来源与现有页面观察范围见主文档第 9 节。具体实现从用户任务与真实赛事内容出发；参考对象只用于分析布局、节奏和交互原则，不复制其代码、美术或品牌资产。

本文的变量与组件契约只约束赛事中心；官网保留自身的主场与参与体验。FryDeck overlay 的画布尺寸、设备参数和转播循环不直接作为网页规范。

## 2. 三种页面模式与密度

全站共用同一套品牌变量和组件语法，但根据任务分为三种页面模式。

### A. Archive / 档案叙事

适用：归档赛事首页、赛季回顾、队伍详情、选手详情。

- 一屏一个视觉主角。
- 允许巨型标题、人物抠图、全宽场景和章节滚动。
- 数据必须与人物或比赛建立直接关系，不能只做装饰。
- 冠军与人物场景提供具体比赛或档案入口；展示英雄与实际比赛使用英雄分别标注。
- 每一页最多保留一个持续滚动场景，其他内容恢复正常文档流。

### B. Index / 赛事数据

适用：现役赛事首页、赛程赛果、晋级形势、参赛阵容、排行榜、英雄与地图。

- 纸色用于索引、表格与持续阅读；深色用于摘要、关键结论和需要突出连接关系的路径工作区。
- 晋级页可以采用完整的深色分流图或签表章节，再回到纸色排名表；用户始终能识别当前赛季、阶段和队伍。
- 使用清晰行列、筛选轨道和固定数字对齐。
- 查询页正常首屏出现筛选与实际结果，进行中的赛事总览优先显示当前阶段和即时赛况。
- 动效用于解释层级、筛选变化和数据更新，不遮挡读取。
- 人物图只用于榜首、焦点比赛或当前选中对象，不铺满每一行。

### C. Control / 工作台

适用：我的空间、比赛房、报名、任务、通知及管理流程。

- 深色界面为主，黄色表示当前任务、当前步骤和下一步动作；完成与错误使用各自状态色。
- 强调状态、权限、截止时间和操作反馈。
- 延续 FC Signal 的清晰分区和操作反馈，借用转播画面的信息层级；文案使用用户实际任务，不引入无关设备参数或频道代码。
- 登录、账户设置、激活、报名、名单及比赛房按完整参与流程组织，并符合网页可访问性。

页面模式由用户的首要任务决定。现役赛事首页是 Index 主导的赛事总览，可以保留一个 Archive 级别的视觉主角；归档赛事首页采用 Archive 叙事。人物与队伍的分析页面使用 Index 密度，档案和历程页面使用 Archive。章节可以在纸色与墨黑之间转换，但导航逻辑、当前上下文和状态含义保持连续。

## 3. 核心原则

1. **先读懂，再感受动效。** 标题、核心数据和下一步入口必须在静止状态下成立。
2. **每个视口只有一个主焦点。** 其他信息通过比例、明度和位置退后。
3. **黄色代表信号。** 用于当前项、关键数字、章节提示和主要操作；档案焦点可以使用整块黄色卡，数据行和操作区保持克制。比赛进行状态使用独立 Live 状态色。
4. **数据决定版式。** 比分、排名、队名和状态使用真实数据；不制造无含义的技术参数。
5. **章节形成连续路径。** 页面之间通过编号、信号带、状态轨和一致的过渡连接。
6. **移动端重新构图。** 手机不是桌面缩小版，保留主结论、人物关系和主要入口。
7. **状态必须诚实。** 正在同步、缓存快照、缺失数据、归档和实时状态不可使用相同视觉。
8. **系统长期稳定，赛季适度变化。** 赛季主题不能重定义导航、基础组件、状态色、数据含义或无障碍行为。
9. **参与者有身份，结论有依据。** 人物图、队伍名、荣誉与比赛记录对应；未知、低样本和缺失不通过文案或图像美化成确定事实。
10. **内容先于制作术语。** 面向玩家的页面说明他们能看什么、做什么；内部设计、同步实现和转播参数只在有助于判断时显示。

## 4. 品牌资产

- 主标志：`/logos/fries-cup-symbol.png`。
- 品牌组合：沿用薯条杯标志与 `FRIES CUP` 字标资产，产品中文副标采用“赛事中心”；英文副标按命名交付统一，不将现有 `DATA CENTER` 继续定义为长期固定名称。不得拉伸标志或随意改变字标比例。`FC SIGNAL` 只用于设计文档、组件预览和内部版本标记。
- 页面身份顺序：Fries Cup → 赛事代码 → 页面名称 → 当前状态。
- 队标保留原始比例和颜色，四周至少保留自身宽度 12% 的安全区。
- 英雄人物图保留透明边缘与完整识别特征；大图统一视觉底线，并在底部使用同一淡化区域。
- 队伍和人物的姓名、身份、职责及档案入口不能被大图遮住。缺少人物素材时保留身份回退，完整名单与幕后署名不因缺图而消失。

固定基础与赛季个性的边界：

| 长期固定（约 80%） | 赛季可变（约 20%） |
| --- | --- |
| Logo 锁定、全局页头、Context Dock、页面网格 | Hero 人物或奖杯选择 |
| 字体职责、数据对齐、组件结构、交互状态 | 低对比度纹理和章节场景 |
| 黄色与状态色语义、筛选和返回逻辑 | 赛事辅助色，但不得覆盖品牌与状态色 |
| 响应式、无障碍、动效关闭和性能规则 | 赛季代码、章节标题和叙事文案 |

素材边界继续遵循 [`design-material-policy.md`](./design-material-policy.md)。

### 产品更名的交付范围

中文“赛事中心”是本版确定的命名方向；文档升级不等于页面已经更名。实际实施时逐项核对：

- 全局字标、副标、导航、官网入口及跨产品返回标签。
- 页面标题、元信息、可访问名称、加载、空状态和错误文案。
- 分享页面、海报、下载图片及其他导出产物的产品身份。
- 中英文对应关系与已确定的英文副标；历史赛事记录及当时已发布材料不追溯改写。

保留现有文件路径、仓库名、域名、URL 参数、`--fc-data-*` 变量和接口兼容性。更名不自动触发技术标识迁移，也不随本次文档更新修改页面代码。

## 5. 色彩系统

下表是赛事中心的现有变量基线。官网的暖纸色与墨黑允许保留自己的数值，跨产品共同职责及黄色面积规则见主文档第 4 节。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--fc-data-signal` | `#f4c320` | 当前项、重点数据、主操作、章节信号 |
| `--fc-data-ink` | `#181a17` | 深色底、主文字、强分隔 |
| `--fc-data-ink-raised` | `#22231f` | 深色悬浮层和二级控制区 |
| `--fc-data-paper` | `#eeede6` | 档案与数据页主底色 |
| `--fc-data-paper-deep` | `#e4e3db` | 相邻章节、表格分组、弱强调 |
| `--fc-data-paper-raised` | `#f6f5ef` | 卡片、弹层和可交互记录 |
| `--fc-data-text-muted` | `#66685f` | 次要说明和元数据 |
| `--fc-data-text-on-dark` | `#d3d5c8` | 深色面板正文 |
| `--fc-data-on-signal` | `#181a17` | 黄色信号面上的文字与图标 |
| `--fc-data-on-paper` | `#181a17` | 纸色表面的主要文字与图标 |
| `--fc-data-on-ink` | `#eeede6` | 深色表面的高强调文字与图标 |
| `--fc-data-focus-on-light` | `#806000` | 浅色表面的焦点轮廓 |
| `--fc-data-focus-on-dark` | `#f4c320` | 深色表面的焦点轮廓 |

状态色分为浅色表面用的深色值和深色表面用的明亮值：

| 语义 | 浅色表面 | 深色表面 | 必须同时提供 |
| --- | --- | --- | --- |
| Live / 正在进行 | `--fc-data-status-live` `#0f766e` | `--fc-data-status-live-bright` `#55cbb8` | `LIVE` 文本或等价标签 |
| Success / 已完成 | `--fc-data-status-success` `#237a4b` | `--fc-data-status-success-bright` `#65c98c` | 完成结果或成功说明 |
| Warning / 需要注意 | `--fc-data-status-warning` `#9a4d00` | `--fc-data-status-warning-bright` `#f0ac4e` | 原因和下一步动作 |
| Danger / 错误或阻塞 | `--fc-data-status-danger` `#b33a32` | `--fc-data-status-danger-bright` `#ff776d` | 错误范围和恢复入口 |
| Info / 信息 | `--fc-data-status-info` `#356f9a` | `--fc-data-status-info-bright` `#79b9e6` | 信息类型或来源 |
| Archived / 已归档 | `--fc-data-status-archived` `#5b625b` | `--fc-data-status-archived-bright` `#b8bcb4` | `ARCHIVED` 文本 |

颜色配对规则：

- 黄色面统一使用 `--fc-data-on-signal`；黄色文字和细线只放在深色表面上，不能在纸色底承担正文、状态或焦点含义。
- 浅色表面使用状态深色值，深色表面使用对应的 `-bright` 值。状态必须同时提供文字、图标或形状，不能只靠颜色。
- `--fc-data-text-muted` 在纸色底上不得继续降低透明度；更弱的信息应调整层级或内容，而不是牺牲可读性。
- 职责色仅承担语义，不参与品牌装饰：`--fc-data-role-tank` 重装蓝、`--fc-data-role-damage` 输出红、`--fc-data-role-support` 支援绿。职责色不能单独承担小字号文字，也必须配合职责名称或图标。
- 黄色表示当前信号，不能同时表达成功、警告和当前选择。
- 归档焦点卡可以使用整块黄色；路线图的黄色用于当前对象及其已确认路径。未发生的可能去向需提供待定或条件说明，不能依靠相同实线冒充既成结果。
- 完整路径区可用墨黑衬托连接关系，排名和持续阅读区使用纸色；变换表面时同步更换文字及状态色配对。

## 6. 字体与信息层级

- 正文与中文标题：HarmonyOS Sans SC。
- 巨型英文、数字、比分和章节背景：Barlow Condensed Black，对应 `--fc-data-font-display`。
- 系统标签和赛季代码：HarmonyOS Sans SC，使用等宽数字特性。
- 当前 `--fc-data-font-system` 引用 `--font-mono`，后者仍指向 HarmonyOS 字体栈；变量名称不要求换成另一套等宽字体。
- 中文不强制全大写式字距；英文系统标签可以使用大写和适度字距。
- 比分、排名、时间和表格数字统一使用 `font-variant-numeric: tabular-nums lining-nums`；Barlow Condensed 不承担中文正文。

建议字号：

| 层级 | 桌面 | 手机 | 说明 |
| --- | --- | --- | --- |
| 场景标题 | `72–180px` | `48–82px` | 首页和档案页限定 |
| 页面标题 | `48–88px` | `36–52px` | 每页一个 |
| 分区标题 | `30–56px` | `26–38px` | 清晰区分章节 |
| 关键数值 | `36–80px` | `32–56px` | 比分、排名、OVR |
| 正文 | `14–16px` | `14–16px` | 不低于 14px |
| 表格与控制 | `12–14px` | `13–14px` | 高频读取内容 |
| 系统小字 | 最低 `10px` | 最低 `11px` | 重要信息不能低于此值 |

`7–9px` 只允许用于 `aria-hidden` 的装饰代码、刻度和背景标记，不能承载时间、状态、按钮含义或筛选条件。

大字承担核心表达，编号和短标签定位内容，数字解释事实。数据和操作页应压缩重复标题与摘要，让实际结果或任务尽早出现；英文标签不能成为中文用户理解状态或操作的唯一依据。

## 7. 网格、留白与几何

- 全局水平边距：`clamp(20px, 3.4vw, 64px)`；手机固定 `16px`。
- 内容最大宽度：`1840px`；Hero 场景可全宽，但文字仍对齐全局网格。
- 桌面使用 12 列逻辑网格，视觉上可显示 4 个主要分区线。
- 间距基线为 8px；常用间距为 8、16、24、32、48、64、96px。
- 面板、输入和小型控制统一直角，`--fc-data-radius-control` 为 `0px`。
- 依靠边线、留白和明度建立层级，阴影只用于弹层和真正悬浮元素。
- 切角、纸张叠放或轻微倾斜可用于少量档案焦点；表格、比赛节点、筛选和操作控件保持稳定对齐。
- 十字定位点、轨道与圆环只辅助表达边界、关系和赛事核心；不添加无数据含义的实时读数。

响应式采用行为规则，而不是简单缩放：

- `≥1280px` 使用 12 列逻辑网格；`768–1279px` 使用 8 列；`<768px` 使用 4 列。
- 手机主边距为 16px；桌面和平板使用全局自适应边距。验收宽度不是额外断点。
- Filter Rail 在手机变为可展开控制区，并始终在关闭状态显示已选条件数量和结果数。
- 数据表优先隐藏低优先级辅助列。只有横向比较不可拆分时才允许横向滚动，并固定首个身份列。
- Hero、详情摘要和操作区在手机必须重新排序；禁止依靠缩小字体保留桌面构图。
- 固定和粘性元素必须考虑页头高度、焦点轮廓、软键盘和安全区，不能遮挡标题或主要操作。
- 复杂晋级图在手机先提供当前队伍的纵向路径和结论，再提供必要的完整横向签表；不能只把桌面图整体缩小。

## 8. 组件语法

### 全局组件

- **Global Header**：Logo、一级导航、赛事选择、语言和账户。
- **Context Dock**：当前赛季、状态、更新时间及页面内二级导航。
- **Sync Notice**：同步、缓存、错误和归档状态。
- **Mobile Menu**：当前页面名称优先，赛事与语言进入同一菜单层级。

### 叙事组件

- **Hero Stage**：唯一主角、关键结论和一条明确去向。
- **Chapter Rail**：页面有四个以上章节时使用；负责当前位置和阅读进度。
- **Section Signal**：章节号、赛事代码和分区名称。
- **Signal Gate**：只放在真正的内容阶段转换处，一页通常不超过两条。

### 数据组件

- **Page Intro**：页码、系统标签、主标题、简短解释和主要状态。
- **Stat Block**：标签、主值、单位和数据范围。
- **Filter Rail**：筛选条件、结果数、重置和视图切换。
- **Data Row / Data Table**：固定数字对齐，整行可点击时必须有明确悬浮反馈。
- **Match Record**：阶段、时间、队伍、比分、状态和入口。
- **Bracket Node**：轮次、队伍、比分、晋级状态；黄色表示当前对象及其确认路径，未来去向另标条件或待定。
- **Dossier Card**：人物或队伍主图、身份、关键数据和档案入口。
- **Empty / Error State**：说明发生了什么、数据是否保留以及下一步操作。

### 基础组件契约

前四个组件延续首轮迁移基础；路径组件补充总览与晋级页已形成的交互要求。页面可以组合它们，不应各自复制一套近似结构。

#### Context Dock

- 组成：赛事身份、赛季状态、更新时间或数据来源、赛季切换器，以及当前一级页面的必要上下文。
- 状态：`live`、`upcoming`、`archived`、`syncing-with-cache`、`error-with-cache`、`unavailable`。缓存、同步和实时不能共用同一句标签。
- 桌面保持一条清晰信息线；手机重新分成身份区和操作区，赛季切换目标不小于 44×44px。
- 页面滚动后可以粘性显示，但不得与 Global Header 重复 Logo、账户、语言或整套主导航。

#### Page Intro

- 组成：可选章节号、系统标签、唯一 `h1`、最多两行说明、主要状态和最多一个主要操作。
- 页面只允许一个主标题。巨型背景字必须是 `aria-hidden`，且不能与主标题形成第二视觉焦点。
- Index 模式在首屏先给出范围、状态和结果；Archive 模式可以增加人物或奖杯，但数据结论必须在静止状态可读。
- 手机按照“状态 → 标题 → 结论 → 操作”重排，不保留只适用于桌面的绝对定位。

#### Filter Rail

- 组成：筛选组、当前条件、结果数、重置和可选视图切换。改变筛选后必须保留明确的结果反馈。
- 可分享筛选、选中对象，以及决定可见记录数量的展开状态写入 URL；临时弹层、焦点、hover 和纯动画状态不写入 URL。切换赛事时只继承仍有意义的条件。
- 手机默认可收起，但关闭时仍显示条件数和结果数；展开、清除和每个选项均可通过键盘完成。
- 无结果时保留筛选条件，提供清除入口，不把“无匹配”写成数据加载错误。

#### Match Record

- 组成：阶段/轮次、日期时间、双方身份、比分或对阵占位、比赛状态和唯一主入口。
- 必须区分 `scheduled`、`live`、`final`、`forfeit`、`cancelled`、`unknown`；不能用 `0–0` 代替未开赛或未知结果。
- 比分使用固定数字宽度。队名和 Logo 预留长文本及缺失素材回退，Logo 不改变原始比例。
- 整行可点击时使用一个覆盖链接并提供明确 hover/focus；需要次级操作时改为显式按钮，禁止嵌套交互元素。
- 手机优先保留双方、比分/时间和状态；阶段、转播等辅助信息可以换行或进入详情，不能缩成不可读小字。

#### Team Route / 队伍路径

- 组成：当前阶段、队伍选择、整体路径、选中对象摘要、逐场记录，以及适用的排名和规则入口。
- 选择队伍后，其名称、路线、战绩和逐场记录共同响应；灰色保留全场结构，黄色突出当前对象的已确认经过。
- 瑞士轮的胜负分流和单败、双败赛制分别按真实规则表达。胜利前进使用实线，失利分流使用虚线，并提供文字结果；单败失利明确止步，不显示不存在的败者组。
- 未发生的对阵、待安排节点和条件性去向使用独立的待定标签及弱化线型，不沿用已发生路径的完整高亮。
- 双败赛制明确落位和最后终点；进入总决赛的席位与夺冠分开表达。胜者组决赛获胜不能直接标为总冠军。
- 每个可进入详情的节点对应具体比赛；轮空、弃权和取消保留各自语义，不伪装成已实际进行的地图或比赛。
- 桌面同时提供关系图与选中对象依据；手机先读纵向摘要，完整图在自身区域内滚动。返回时恢复有意义的赛季、阶段与队伍选择。
- 有旧快照时显示其时间和同步结果；数据暂时不可用时说明影响范围，不用空路径暗示队伍从未参赛。

## 9. 动效系统

| 层级 | 时长 | 用途 |
| --- | --- | --- |
| Quick | `160ms` | hover、pressed、颜色反馈 |
| Interface | `240ms` | 下拉菜单、筛选、局部展开 |
| Reveal | `620ms` | 分区标题和记录依次进入 |
| Scene | `900ms` | Hero、章节切换和重要构图变化 |

- 入场优先使用 `opacity`、`transform` 和独立 `translate`，避免触发布局重排。
- 同组记录间隔 60–100ms，最多连续错开四项。
- 指针视差不超过 10px；持续旋转或播报循环不短于 18 秒。
- 不使用自动轮播；用户滚动或点击后才改变主要内容。
- 页面没有 JavaScript 时，核心内容保持可见。
- Archive 模式最多允许一个 Scene 级持续滚动场景；Index 模式以 Quick、Interface 为主，只允许一次性 Reveal；Control 模式不使用视差和 Scene 动效。
- 系统 `prefers-reduced-motion` 和页面“动态关闭”共同生成一个 `reducedMotion` 状态，并向场景根节点写入 `data-reduced-motion="true"`。用户手动关闭的选择保存在本地；系统减弱动效不能被页面强制覆盖为完整动效。
- 减弱动效时直接呈现最终内容，停止视差、持续旋转、错峰延迟和滚动驱动的位移。只把时长改成 `1ms` 不能替代 JS 和滚动逻辑的停用。
- 路径切换、筛选和操作立即响应，动效解释关系变化，不作为等待阅读结果的前置步骤。官网声音体验不自动延伸为赛事中心背景音乐要求。

## 10. 交互状态

- 当前项：黄色底或黄色实线，至少再配合文字、形状或 `aria-current`。
- Hover：背景明度变化 4–8%，可辅以 1–2px 位移。
- Focus：浅色表面使用 `--fc-data-focus-on-light`，深色表面使用 `--fc-data-focus-on-dark`；外框不能被 `overflow` 裁切。
- Disabled：降低对比度并移除位移动效，保留原因说明。
- Loading：显示真实同步状态；有旧快照时明确标注“正在同步”。
- Error：说明影响范围，保留可继续浏览的内容和重试入口。

移动端点击目标至少 44×44px。仅靠图标表达的按钮必须提供可访问名称。

### 赛事总览

进行中：`赛事身份与当前阶段 → 正在进行或下一场比赛 → 当前局势与关注入口 → 完整赛程、晋级和阵容`。

归档：`冠军或已发布赛季结论 → 人物镜头 → 赛季图谱 → 关键比赛与人物记录 → 赛季回顾`。

主场景只保留一个主焦点，相关比分和人物身份始终可读；每个叙事结论可继续进入具体记录。进行中赛事不能直接沿用冠军典藏首屏；无已发布冠军或荣誉时使用真实状态，不由排名推定。查看归档样板不能替代进行中赛事验收。

### 赛程赛果

共用两项导航：归档赛事为 `赛事精选 / 完整赛程`，进行中赛事为 `赛程总览 / 完整赛程`。内容与全局页头、赛事状态条共用左右边界；入口页不再叠放一条重复的章节导航。

归档精选：`简短标题与公开场次 → 一场真实重点对阵及队伍查找 → 两场带有明确看点的对阵 → 紧凑赛果行`，全页最多八场。主卡以双方身份、系列赛比分和全部已发布单图赛果为主视觉，胜方简称以薯条黄强调。明确配置的精选场次及首位主卡优先保留；自动精选在有记录的其他阶段中补充代表性比赛，使赛季回看能覆盖瑞士轮、小组赛或突围赛。无相应记录时不补造阶段或故事。

比赛看点使用逐图结果核实。只有已完成、非判罚、地图记录齐全、单图胜方与比分一致、累计图胜与系列赛比分相符，并符合已知赛制时，才描述比分追回过程或决胜图；平局不计图胜。缺失或矛盾的记录退回普通赛果表达。文字说明从谁的视角由多少比多少追到最终比分，并链接到该场逐图战报，避免笼统称为冠军路线或转折点。

手机将搜索和阶段入口置于主卡上方，压缩说明与计数，收起主卡旁重复的完整赛程按钮；保留顶部双导航和列表末端入口。两张精选卡顺次展示，其余比赛使用紧凑行，保持双方身份、比分与实际轮次可读。

完整赛程：`阶段选择 → 队伍搜索与更多筛选 → 已选条件及场次 → 轮次索引与对阵记录`。一般浏览按轮次查看；搜索队伍或由队伍档案进入时，按轮次连续展开全部匹配对阵，索引用于定位。桌面轮次索引可独立滚动，手机使用原生轮次选择器。切换轮次让结果进入视野；清除筛选同时清除旧查询别名和轮次位置，保留赛事、设计版本与语言。

精选和完整列表共用队伍搜索候选：显示真实队徽、简称、全称及本届公开赛程条数，按明确身份去重。简称或全称的唯一精确匹配优先；点击或使用方向键选择候选后携带队伍 ID，区分 NF 与 NFA 等相近名称。未选择候选时保留模糊查找；同名多身份不自动代选。支持回车、Esc、焦点离开关闭及中文输入法组合态保护。列表切换队伍保留阶段等已有条件，输入新查询清除旧队伍 ID。

轮次标签共用公开字段映射：中文显示“瑞士轮第 1 轮”“胜者组决赛”等；小组比赛保留组别和比赛日；未知名称保留源值。列表保留弃权和判罚结果、排除轮空。单图缺失的一侧比分显示 `—`，不补为零；只给出比赛日期的记录不把排序时间当成开赛时间。比赛详情返回时恢复原队伍、筛选、轮次和浏览位置。

2026-09-11 本地实现与验证见[首批赛程整理记录](fc-signal-schedule-polish-20260911.md)和[精选及搜索精修记录](fc-signal-schedule-refinement-20260911.md)。本轮改造归档精选与完整列表，进行中赛事的主视觉继续沿用已有入口，单独进行后续设计与验收。

### 比赛详情

`赛事与数据状态 → 比赛概况与比分走势 → 连续逐图战报 → 选手数据与对比 → 录像资料`

比分是主角，双方队徽、实际地图结果和已发布选手数据共同建立比赛身份。概况沿用墨黑底、纸白文字与薯条黄胜方强调；地图章节保持可连续阅读的双队统计，英雄图不遮挡表格。详情复用目录的紧凑赛事状态区，保留更新失败、已有记录与重试入口。

比分下方可提供一句有逐图记录依据的比赛摘要，与赛程精选共用核验逻辑；仅在逆转或决胜图事实成立时显示，缺图、矛盾、判罚与弃权不生成此类叙事。全场 MVP 把已有英雄图放在选手身份旁，右侧集中评分和关键统计；手机优先身份、评分和完整数字，评分说明可独立展开。

章节导航提供比赛概况、逐图战报、选手数据和录像资料；有实际选手统计时提供常驻查找入口。查找直接展开选手工作区并聚焦输入，桌面使用文字与图标，手机使用带可访问名称的图标。由对位比较返回查找时保留双方选择、搜索与职责筛选；选手工作区位于全队汇总和职责领跑者之前。

逐图统计默认展开，可分别收起，也可统一展开或收起；收起后仍保留本图比分、时长、已记录阵容和资料入口。地图索引标明本图比分，概况走势与章节内的累计比分分别使用“每图后的大比分”“本图后大比分”，不混淆单图结果和系列赛进程。章末把代码复制、录像入口及按实际记录顺序的上一图、下一图合入同一工具栏；手机自然分行，触控按钮至少 44px。

宽桌面使用侧边地图索引，窄桌面和手机改为横向索引，为完整统计留出空间。地图落点计入实际固定页头、章节导航与地图索引高度；横向索引保持当前图可见。查人、比较、折叠与地图选择保留网址中的赛事、语言、筛选及回程状态，进入档案再返回后恢复原上下文。弃权或缺少实际选手统计时不提供空的查找与对比入口，登记名单不表述为已确认出场。

本地首版实现与验证见[比赛详情精修记录](fc-signal-match-detail-refinement-20260911.md)，本次范围的最终版本见[比赛详情收尾记录](fc-signal-match-detail-finish-20260911.md)。设计收尾、功能验证和正式发布分别记录。

### 晋级形势

`阶段摘要与阶段选择 → 选中队伍及整体路径 → 逐场依据与排名 → 规则说明`

瑞士轮先解释胜负如何分流，季后赛先解释选中队伍如何前进、落位或止步，最终结果提供已发布名次和冠军经过。按照 Team Route 契约使用黄色、线型与状态，不把装饰线当成已确认的去向。当前查看阶段与赛事实际最新阶段分别标明。

### 参赛阵容与队伍详情

目录页使用 Index 模式；详情页使用 Archive 模式。阵容门户、队伍、选手、职员目录采用一致的导航和筛选顺序，移动端优先提供可检索名单。队伍详情需重新组织身份、赛季结论、完整阵容和比赛记录，整合重复的核心成员与完整名单展示；保留可靠的数据、导航和分享逻辑，页面及实际分享产物共同验收。选手档案保留有效人物主视觉，移动端身份信息应在首屏可读。

#### 目录共同模板

2026-09-10 确认选手目录作为 `/players`、`/teams`、`/staff` 的共同基准，目标为“快速找对象，也愿意停下来浏览”。各目录使用 [RosterDirectory](../src/features/roster-directory/RosterDirectory.jsx) 与同一份样式，页面只提供名单、筛选字段和对象预览。2026-09-11 将职员目录分为战队职员与赛事职员，两类继续共用该模板。

| 固定部分 | 实施规则 |

#### 五项导航与职员分类

阵容子导航固定为 **阵容总览 → 参赛战队 → 参赛选手 → 战队职员 → 赛事职员**。桌面五项等宽、文字左对齐，以细竖线区隔；当前项的黄色底线覆盖整格，整格均可点击。窄桌面允许中文与英文代号上下排列；≤760px 隐藏辅助英文，保持至少 100px 的单项宽度，导航内部横向滑动，当前项在进入页面或调整宽度后保持可见，文档外层不横向溢出。键盘焦点与当前栏目分别可辨。

| --- | --- | --- |

赛事职员的对外职务名称统一为“赛管”和“解说”，英文为 Officials 和 Casters。导航入口、筛选、署名、预览和来源说明均采用这两类称谓。

赛事职员目录默认按已发布比赛署名场数降序，场数相同按姓名稳定排列；总览中的赛管、解说名单分别采用相同顺序。目录保留昵称、职务顺序的手动选项，筛选时保留手选排序，清除全部后恢复场数降序。战队职员默认仍按职务顺序，原版综合目录沿用原有排序。署名数量用于浏览记录，不表达工作量或贡献排名。

总览分别提供上述四类目录入口和对应记录数。职员按实际档案计数，同队兼任经理与教练保留一份档案、两个职务，跨队及不同赛事署名类别可分别出现；不得把角色数量相加冒充去重人数。筛选标签、标题和来源说明随类别变化，字号、布局、名单操作及预览结构保持一致。

### 数据排行与选手详情

排行榜使用 Index 模式，榜首可以拥有一块人物档案区，主体表格保持高密度。选手详情使用 Archive 模式，人物、职责、赛季表现和比赛记录形成连续档案。

排行入口：`紧凑赛事状态 → 数据分区导航与短标题 → 职责、查找与筛选 → 结果条数、评级状态和统计口径 → 完整榜单与选手预览`。标题与说明不再叠加独立英文眉题；手机合并重复阅读说明，具体计算依据仍可展开查看。排行首屏压缩不自动套用于英雄、地图或完整人物档案。

- 计数单位为“职责记录”：一名选手可以在不同职责各有一条记录，不把记录条数写成选手人数。职责入口显示全季正式条数，并明确标注“条正式排名”；结果区显示当前筛选范围的总记录、正式排名、暂定评分与未评级条数，提供直接可见的“只看正式排名”。样本门槛从现有赛季评分规则读取，筛选不重排正式名次。
- 综合榜、重装、输出、支援组成完整职责导航，桌面四栏等宽，700px 以下两行两列；名称与次级数量左右对齐。选中栏保留黑底、浅字与黄色底线，其他栏用纸面和细分隔线。最窄屏缩小内边距，保证完整标签、等高与至少 44px 操作高度。
- “更多筛选”展开为常用英雄、最低职责出场时长、关注范围三等宽栏，使用纸面、细线和至少 44px 的控件。时长保留本职责累计分钟口径，空值明确显示“不限”；关注范围使用“全部选手 / 仅看关注”两段切换。760px 以下英雄与时长并排，关注范围独占下一行。展开箭头与已选条件数分别显示；收起后保留条件标签、逐项取消和清空筛选，筛选与 URL、正式名次及评分规则的关系不变。
- 评分依据采用 `评分摘要 → 样本状态 → OVR 形成过程 → 原始表现贡献 → 可展开的完整计算依据`。正式条目默认收起样本门槛，暂定条目展示距正式排名的缺口，未评级展示暂定评分门槛与所缺记录。地图、分钟、比赛数与评分上限均读取当前评分模型。
- 原始表现贡献与赛季 OVR 分开标明：贡献图给出正负方向、0 中线、相对原始分 50 的含义及权重，不能将贡献值直接解释成 OVR 加减分。摘要仅依据已知贡献生成；缺失依据、场数或评分保留明确缺失状态，不补成 0。未评级不展示数值计算或贡献结论。
- 对手修正前的数值统一称为“基础 OVR”。仅在实际校正量明确为 0 时显示“本次校正未改变评分”；缺失校正量不作此判断。
- 完整公式、对手记录、冻结或动态基线与模型版本保持可核对。Signal 评分弹层自身提供设计属性，使 Portal 正确取得纸白、黑色、黄色及语义色变量；原版弹层保留既有呈现。原生弹层保留 Esc、焦点约束、嵌套关闭和返回原评分入口。
- 点选名字打开预览，名字旁使用“预览”提示；箭头用于明确的完整档案入口。预览聚合姓名、所属队伍、职责与赛季总评，完整档案和加入比较按钮随后出现，样本和核心统计继续保留。窄屏以弹层呈现，关闭或加入比较后恢复到原选手入口。
- 比较选取 2–4 位同职责选手。只选一位时，主按钮带用户进入同职责榜单并清除姓名查询，保留队伍等其他筛选；达到上限或职责不符时，禁用项说明原因。比较基准、差值、统计口径与已有缺失值规则保持一致。
- 比较弹层的头像与姓名并排，职责样本、队伍、英雄和基准标识保持可读。桌面由数据区承担纵向滚动，表头和指标名固定，说明置于表尾；699px 以下或可用高度不超过 600px 时，改为整段纵向阅读，表格只在内部横向滚动。每种布局只保留一个纵向滚动区域，关闭入口保持可见。
- 预览与比较面板都可进入完整选手档案。离开时保存排行阅读位置；返回保留 URL 中的赛季、职责、筛选、排序、页码、指标视图、预览对象和比较选择。比较弹层本身不强制重新弹出，已选对象留在比较栏。
- “只看正式排名”使用文字在左、直角矩形开关在右的独立控件，外框与滑块均不使用圆角；关闭为纸灰底，开启为薯条黄底及右移的墨黑滑块。整项至少 44px 高，采用 switch 语义并保留键盘与焦点反馈。该常驻开关不生成筛选标签，单独切换时不新增筛选行；开启时评级摘要只显示正式排名条数，关闭恢复完整分布。英雄、队伍、时长等条件继续显示可取消的标签，无结果仍提供清空筛选入口。“显示差值”复用同款开关；“选择列”保留多选框语义，以直角细框、墨黑选中底与黄色勾号表达状态，每项至少 44px 高，保留键盘与焦点反馈。完整指标与多人比较允许内部横向滚动，外页不因表格变宽。

本地实现与验证见[数据排行精修记录](fc-signal-leaderboard-refinement-20260911.md)及[职责导航与评分依据收尾](fc-signal-rating-explanation-polish-20260911.md)。完整人物档案、英雄与地图页保留各自实施范围。

### 英雄与地图

选手排行、英雄数据、地图数据沿用参赛阵容的分区导航语言，并共用 `SignalSectionNav.module.css`。三项等宽铺满可用宽度，文字左对齐，中文旁附 RANKING / HEROES / MAPS 辅助英文；英文界面只显示英文名称。使用细竖线分区，当前项采用墨黑粗体与覆盖整格的 3px 黄色底线，悬停使用浅纸灰底色，整格可点击。桌面最小高度 56px、左右内边距 18px；761–1100px 中文与辅助英文上下排列，760px 以下隐藏辅助英文、最小高度 48px。入口数量保留三栏，与阵容五栏共同遵循相同状态、字号和间距规则；下方职责与模式筛选继续使用黑底选中块。目录页不显示 `DATA / 01–03` 编号；详情页右侧保留来源返回，手机为其独立预留 44px，分区入口仍保持等宽且外页不横向溢出。

使用图谱式目录。图片用于识别，数据排序和筛选仍是主任务；不要把所有英雄同时做成大型海报。

英雄索引沿用数据排行的紧凑赛事状态、数据分区导航与短标题。全部英雄、重装、输出、支援组成四栏等宽职责导航，窄屏为两行两列；选中栏使用黑底、浅字与黄色底线。数量明确表示本季已收录的英雄数，不表示选手人数。搜索与排序单独成行，支持英雄中英文名称和别名。

- 默认浏览呈现三个职责的高频英雄，桌面展示每个职责前三位记录；手机保留每个职责的首位英雄、立绘及记录出场率，压缩重复说明。并列最多时明确标注并列，不推断版本强度。
- 完整索引按出场次数、使用选手数或名称排序。筛选后显示当前结果数量，提供清除筛选与统计口径入口；保留全季出场序号及同一出场率分母。切换为使用选手排序时，主数值与解释同时换为去重后的选手数。
- 记录出场率 = 该英雄出场次数 ÷ 有可识别英雄信息的队伍单图样本。同一英雄在同一队伍、同一张图只计一次；双方都有记录时计两次出场，在比赛列表中合为一条地图记录。单图裁决、未发布记录与无法识别的英雄标签不扩大分母；不把赛后记录描述为全程阵容、精确使用时长、熟练度或版本强度。
- 英雄档案以姓名、立绘与记录出场率建立识别，数字区可直接进入使用选手、出场地图及比赛记录。手机为两列数字区，图像在文字附近减淡，完整数据与标签保持清晰。
- 选手和地图行的数量进入相应证据过滤；比赛链接进入准确的单图。由英雄档案进入选手档案或比赛后，返回保留英雄、索引条件、比赛过滤与阅读位置。索引、英雄档案与证据筛选均以现有 URL 状态为准。地图相关回程按下方约定执行。

本地实现与验证见[英雄数据页第一版精修记录](fc-signal-hero-data-refinement-20260912.md)。

地图索引沿用紧凑赛事状态、数据分区导航、短标题和独立搜索排序。模式入口按实际已收录模式等宽排列，全部模式入口与各模式使用相同选中语义；手机为三列自然换行。入口数量明确为地图记录数，搜索结果另列地图数量，筛选不改变全赛季占比分母。

- 地图实景负责识别。桌面列表可悬停或聚焦预览，点击进入完整档案；窄屏保留带实景缩略图的完整列表。预览中的记录数排名固定使用全赛季记录数名次，不随名称或时长排序变成其他含义。
- 地图档案首屏以名称、实景与已发布记录数建立身份。模式内占比、全赛季占比、平均时长与参赛队伍分别呈现；两种占比紧邻标明各自记录数分母，平均时长标明有效时长样本数。同模式比较沿用同一模式分母。
- 地图记录包含已结束系列赛中的有效具名赛果；裁决仍计入赛果记录，时长和英雄样本排除裁决。地图记录数可以与英雄资料的覆盖记录数不同，不为数字一致而修改口径。
- 英雄、队伍、阵容、阶段、搜索和展开状态写入地图档案 URL。进入选手、队伍、英雄档案或具体比赛后，返回恢复对应筛选和已保存的阅读位置；页内章节跳转保留来源。数据分区导航始终指向所属资料分区，来源返回入口可以指向英雄档案。
- 地图索引、档案和原版分别检查；原版路由、底层统计与赛果数据不因视觉精修改写。

本地实现与验证见[地图数据页精修记录](fc-signal-map-data-refinement-20260912.md)。

### 我的空间

使用 Control 模式。任务、通知、队伍身份和比赛房状态必须比装饰更醒目；从激活、登录、报名、名单到比赛房形成连续参与流程。当前任务、权限、期限、恢复操作与历史记录按实际角色显示。

## 12. 实施依赖与历史记录

下列为可复用的基础实施依赖，不是 2026-09-09 的剩余任务清单。2026-09-05 复核曾将赛程列为下一步，其后安排阵容、数据、进行中赛事、账户和正式替换；该[视觉计划](fc-signal-visual-audit-and-rebaseline-20260905.md)保留当时判断。继续实施前结合较新的专题记录与实际代码确认范围，保留已完成且有效的设计。

8. **全站精修**：统一文字、响应式、空状态、加载、无障碍和性能。

每完成一个一级导航分组，同时处理它关联的详情页；不要只换列表页外观而留下跳转后的旧页面。

每个迁移单元必须同时交付：列表/入口、关联详情、真实筛选与返回路径、加载/缓存/错误/空状态、桌面与手机验证。只完成静态首屏不算该单元完成。

## 13. 页面验收标准

- 先按[品牌主文档](fries-cup-design-system.md)核对主角、色彩职责、叙事依据、产品身份和适用模式，再执行下列实现检查。
- 真实数据、链接、筛选和权限行为保持不变。
- 1440、1280、1024、390 和 320px 的文档外层无横向溢出；必要的签表与比较表内部滚动单独检查，保证提示和操作可用。
- 中文与英文完成布局检查；赛季回顾等支持韩文的页面额外检查韩文。
- 可见图片满足 `complete && naturalWidth > 0 && naturalHeight > 0`。
- 键盘导航、焦点、下拉菜单、弹层和返回路径可用。
- 动态开启、动态关闭和系统减弱动效均可读取全部内容。
- 缓存快照、同步、归档、实时、空数据和错误状态均有独立表达。
- 黄色和状态色必须按规定表面配对；普通文字至少满足 WCAG AA，对焦点、边界和状态图形至少检查 3:1 非文本对比度。
- 每种页面模式至少覆盖一个桌面与手机的完整真实流程；状态验收以该页面实际可能出现的状态为准，不制造无效演示状态。
- 首屏能认出品牌、赛事和对象；查询页能开始查找并看到结果，人物页能看到身份，操作页能看到当前任务或下一步。多层页头与大标题不得共同挤走主要内容。
- 路径页面实际切换至少两支具有不同经历的队伍，核对图、摘要、排名和逐场记录的对应关系，以及进入详情后返回的状态恢复。
- 分享与导出页面打开实际生成的产物，确认名称、队伍、比分、荣誉、范围和状态与网页一致；网页截图不代替导出验证。
- 首屏不预载不可见章节的大图或视频；人物图继续使用响应式尺寸和失败回退，并在构建前后检查新增资源体积。
- 定向 ESLint、生产构建和真实浏览器流程通过。
- 不把本地通过写成已部署；发布后另做生产环境验收。

纯文档更新只检查术语、相互链接、规范冲突和修改范围，不为此运行应用构建或把历史测试结果当作本次验证。
