# 内部队伍实力引擎 v0.1

状态：离线实验。2026-09-26。与公开个人 OVR 分离，不接管分组或报名审核。

## 预先固定的实验方案

首轮运行前固定四个候选，不根据全高杯结果反复挑选参数：

1. `elo`：所有队伍初始 1500，K=32，每个正常系列赛一次更新。
2. `glicko`：原始 Glicko 的评级及 RD 更新，初始 RD=350、最低 RD=50，时间漂移为 5 点/√天。
3. `roster`：Glicko 加历史阵容继承。实际换人只能在赛后被观察，下一场才能受益。
4. `performance`：在阵容模型的预测 logit 上加入历史表现差的正则化系数。模型参数仅使用此前日期拟合；全高杯使用 FCA/FCR 冻结系数。

基础公式参考 [Mark Glickman: The Glicko system](https://www.glicko.net/glicko/glicko.pdf)。代码包含论文数值算例验证。所有额外规则是本项目的实验假设，不代表论文验证过本赛事场景。

以 Asia/Shanghai 比赛日为更新期。同日全部先预测，再更新；不依据排定开赛时刻猜测另一场已结束。使用赛果胜=1、平=0.5、负=0。预期得分仅在无平局时等于胜率；不拟合独立平局概率。

## 数据边界

- 默认读取 Stats 现有 FCA/FCR/QGCS4 本地公开归档，并记录每份文件的 SHA-256。归档不自动等于线上最新版本。
- 复用已有正常赛果过滤器；轮空、弃权、判罚、无日期、重复 ID、矛盾赛果不参与评级。
- 从正式地图统计重建出场名单，不用当前注册名单反推过去。重复地图序号、跨边重复选手、队伍不一致、职责矛盾和部分出场拒绝作为完整阵容。
- `team_a_stats`/`team_b_stats` 与 `player_stats` 同时存在时校对副本，冲突不猜测。不合并历史日志，避免重复计数。
- 赛果、阵容、表现是三种独立覆盖状态。缺失统计不按 0 分处理。全图均为 0 的统计列保守视为不可用。
- 英雄职责缺失时仅允许从明确英雄配置恢复，记录恢复数量。英雄/统计不足可保留赛果而不产生表现信号。
- 申报段位只展示原始分布，不作训练标签，也不将缺失段位补成黄金。不输出“虚报概率”。

## 阵容与表现

地图记录按选手 ID + 实际职责组成五个位置的出场权重。新旧阵容的重合度为逐位置最小权重之和除以 5。只在当天每场阵容覆盖均达到 80% 时更新阵容；阵容变化使历史均值向 1500 收缩，并扩大 RD。收缩与赛果更新分别记录。

地图统计转成每 10 分钟，再取 log(1+x)。依据前日已有同英雄/职责基线标准化；英雄样本不足时回退职责。异常值限制在 ±2 个标准差，死亡反向，其余可用指标等权。每人至少两个可用指标，每张图必须十人完整；先算每图双方差再在系列赛内平均，不把五名选手或多张地图当作多场独立胜负。

用历史比赛学习“赛前实力差 → 预期统计差”，其残差进入队伍近期表现。近期衰减 0.8、先验样本 4；预测系数使用 L2=8 正则，至少 20 条可用记录再拟合。当天统计在当天所有预测之后才能进入历史基线。该信号是探索性统计表现，不代表纯个人技术。

各赛事基线、队伍评级和阵容历史独立。完整 BattleTag 交集只导出身份核对清单，不自动合并；同一赛事不连通的对战网络也分别标明比较范围。

## 评价与分档

按 FCA → FCR → QGCS4 的时间顺序执行。模型选择只比较 FCA/FCR 各赛事等权平均 log loss；同分优先较简单模型。全高杯执行前冻结系数，之后仅更新其自身比赛历史，不重拟合系数或选择模型。

非平局系列赛报告 Brier、log loss、预测准确率；预测五五开计半个正确。所有候选使用完全相同的比赛集合，同时单列双方均已有至少 3 场历史的集合。按比赛日做配对 bootstrap，保留组内依赖；重复队伍跨日依赖仍是限制。

报告中的评级区间为均值 ±1.96 RD，是近似模型区间，未验证真实覆盖率。“样本达标”要求 6 场、3 个不同对手、最近阵容连续可核对 3 场、RD≤200、阵容覆盖≥80%；不等于自动获准用于正式分组。未出场为未评级，其他不足为暂定。

实验分档边界为 A≥1700、B≥1500、C≥1300、D<1300，区间可能跨档。分档只在样本达标时展示，按赛事/连通分量解释，不对应游戏段位。新队不自动进入最低档。

这些归档此前已有分析，无法声称全高杯是从未接触的盲测。最终采用必须再看新周赛的前瞻预测。

## 运行与产物

`npm run analyze:team-strength` 将在 `artifacts/internal-team-strength-20260926/` 输出内部 JSON、逐场预测、身份候选、Markdown 报告和可交互 HTML。`npm run test:team-strength` 验证关键数学、数据和时间边界。

`npm run preview:team-strength` 在 `127.0.0.1:3066` 显示生成后的报告，仅绑定本机。页面可筛选赛事与队伍、查看同日更新明细并比较同一范围内的对阵。

输出目录必须在仓库 `artifacts/` 下，避免覆盖正式网页或发布数据。CLI 可用 `--output artifacts/<目录>` 指定独立实验目录。固定输入与模型代码哈希写入报告以便复验；原始统计和个人 OVR 均不改写。
