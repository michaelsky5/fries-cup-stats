# 公开 UI 发布前验收

日期：2026-09-14。

本轮完成本地生产候选的公开页面验收与针对性修复。尚未提交、推送、部署或修改正式域名；真实手机、账户后台和目标托管环境仍需独立验收。

## 本轮修复

- 繁体首页进入赛季回顾时，根路由原本可能沿用已有 loader，导致回顾转换字库尚未加载就渲染正文。路径变化现在会重新执行语言资源检查；相同语言参数下的站内跳转也会等待所需资源。
- 首次加载完全失败时，顶部改为“加载失败”，不再显示“数据更新于”。没有历史数据时只保留正文中的说明和重试；已有数据刷新失败继续显示旧记录及对应提示。
- 繁体界面与回顾中的职务统一为“賽管”，并修正旧词库替换造成的“周賽務理員”。同步修改源词库、覆盖词条与繁体生成文件；不改公开姓名、账号名或比赛记录。回归检查覆盖职务和姓名保护。
- 404 与页面错误统一使用 FRIES CUP EVENT CENTER，繁体标题正确翻译，保留当前赛事、语言及直角返回操作。
- 公告时间轴改为计划日期状态。例如赛前备份中的日期已过去时显示“计划日期已过”，不据此断言比赛已结束；附注说明实际赛况以已发布赛果为准。四种语言均有明确文案。
- 原版首页的英文比赛复数修正为 matches。

设计实现规范更新为 2.5.41。本轮没有调整评分、赛事数据、参赛权限或页面整体视觉结构。

## 数据失败与恢复

使用最终 RC4 构建，在独立本地测试端口模拟故障；测试夹具限制外部连接，避免真实远端回退掩盖失败。主候选不添加这些限制。

1. 已载入 FCR 数据后阻断公开接口与随包数据：仍保留 286 条排行，顶部提示“更新失败”与旧记录来源。
2. 没有历史快照的另一来源首次访问，接口与随包数据均不可用：显示“加载失败 / 暂无数据”，正文有唯一的重试入口，没有虚构旧记录。
3. 恢复夹具接口后，分别点击两个页面的“重新获取数据”：都恢复为“数据更新于”，排行包含石头及 286 条记录，手机页面未溢出。

夹具只改变本地测试服务的响应，不修改浏览器存储、生产接口、真实记录或候选代码。失败场景中的 503 与 CSP 拦截是预期测试条件；账户 API 的 503 则是这个公开 UI 预览主动隔离后台的结果。

本机通过主候选代理读取完整公开快照时：FCR 返回 200，约 4.7 秒、4.93 MB；FCA 返回 200，约 5.5 秒、5.61 MB；一次 QGC 请求在 30 秒超时。浏览器后续实际取得 QGC 200 响应，主候选能显示 NF 冠军及最终排名。记录显示可恢复，但不足以断言网络稳定；本轮没有确认超时发生在链路、代理还是上游服务。

## 预览与发布边界

最终新版本地预览：<http://127.0.0.6:3052/?lang=zh&season=FCR2026>。

预览只监听本机回环地址，手机不能直接通过这个地址访问。源文件与输出都固定在候选目录，继续编辑工作区不会自动更新它。预览由本轮 `serve-candidate.mjs dist candidate-rc4` 启动。

验收结束后已停止本轮临时故障服务与视觉回退服务，保留 3052 的最终预览。

继续发布前需要：

1. 在目标托管环境复核公开 API 代理、完整快照传输、静态资源和缓存，特别是 QGC 的超时与恢复。
2. 用实际目标手机浏览器检查滚动、触控、底部导航、弹层及分享保存。
3. 单独确定账户后台、真实登录及邮箱流程的发布范围和验收结果；本候选的账户请求明确返回不可用，未进行账户写操作。
4. 固定批准的发布内容、环境和线上原部署备份，再执行正式切换。当前工作区含有多个任务的未提交内容，不可将本轮公开 UI 通过解释为整站可整体发布。

`visual-fallback/` 是同一源码的旧视觉版本，不能替代上一线上部署的完整回退包。恢复视觉需要重新部署对应构建；本轮没有发布或修改数据库。
