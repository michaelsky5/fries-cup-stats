# 手机端产品结构：App / 小程序基础

设计目的：让观众快速找到比赛与数据，让参赛者直接进入下一场和当前待办。现有 Stats 作为客户端信息架构与业务状态的基础。

视觉方向：FC Signal 的 Editorial / Industrial 语言。沿用黑黄浅色底、左对齐标题、清晰分隔线和强调操作。

颜色：`#181a17`、`#f4c320`、`#eeede6`、`#f6f5ef`、`#a77f00`，优先使用已有 `--fc-data-*` tokens。

字体：正文 FCA Harmony（HarmonyOS Sans SC），数字与展示标题 FC Data Display（Barlow Condensed）。沿用已有品牌字体栈与 CSS Modules；不额外引入字体、样式框架或图标依赖。品牌与触屏任务布局优先于通用原型技能的非对称布局默认要求。

布局：四个稳定主入口“赛事 / 比赛 / 数据 / 我的”；赛事目录与语言设置由顶部菜单进入；我的首页先显示当前任务和比赛，其他功能进入子页。子页提供回到我的首页的明确入口。

状态：按赛事、赛事工作区与账号分别保留栏目 URL、筛选、列表页次与滚动位置；详情沿用已有来源返回状态。只存导航状态，不存表单、凭据或邀请参数。

验证：排行搜索后跨 Tab 返回、列表到详情再返回、赛事切换隔离；负责人与观众的我的首页、任务与消息入口；简中、繁中、英文、韩文；桌面与手机相邻路由回归。本机账号样例与线上真实账号验收分开记录。

## 本轮交付

本轮落实第一批的信息结构，并把设置、队伍管理和比赛房中与导航直接相关的问题一起解决。当前成果是现有 Stats 的手机界面基础，代码未发布；App 与小程序各自的页面栈、登录、分享和通知仍需后续实现。

- 固定四个主入口：赛事、比赛、数据、我的。阵容、晋级、回顾、语言与设置从顶部菜单进入。合作方试用版继续遵守原有功能开放边界。
- 跨栏目保留搜索、筛选、比较对象、页次、对象详情来源与滚动位置。公开状态按赛季保存；参赛栏目同时区分赛事工作区和账号。导航缓存只允许已知路径及阅读参数，排除凭据、邀请链接和表单内容。
- 我的首页先显示可进入的比赛和首项待办，再给常用功能列表。详细参赛进度进入独立子页；待办、消息、队伍、关注、角色任务有明确的返回入口。未关联队伍的已登录观众也使用同一结构，功能按现有权限显示。
- 账号设置使用功能列表进入单个编辑页；编辑中的离开确认继续有效，手机保存栏留出底部导航空间。
- 本周名单与可赛时间放在当前任务位置。增员及所有权交接进入独立管理页；首次报名的队伍管理区域收起。权限、审核、截止时间、重复提交限制和草稿保护继续使用原有逻辑。
- 比赛房名单面板直接显示名单。局部面板使用一个历史记录，切换面板不累加记录；浏览器返回先关闭面板，再返回上级。

桌面继续保留现有导航、空间栏目和工作区布局。未增加依赖，也未改变数据库、接口、计分规则、真实邀请或邮件发送。
