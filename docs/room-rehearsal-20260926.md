# 比赛房完整演练 · 2026-09-26

使用独立本机 PostgreSQL、合成队伍/账号和明确标记的合成截图。没有对真实比赛或公开积分榜写入测试数据。

## 浏览器实际完成

- A/B 队长、A/B 普通选手、赛管分别登录；之后使用周赛管理员执行审核及结算。
- 首图选择权由双方确认，无强制理由；选择地图/攻防与英雄禁用分步进行。
- 首图 A 队交换重装/支援职责；首发按 CCTNN 排列。第二图 B 队用替补换下一名输出。
- 双方首发、Ban 顺序、英雄禁用、准备确认、赛管入房检查、开赛和逐图结果。
- 技术暂停、双方恢复响应及赛管恢复。旧版并发恢复产生版本冲突；本次后端修复通过真实数据库并发回归，浏览器当时通过重新同步完成恢复。
- B 队普通选手发起私密赛管协助；赛管回复并解决；A 队看不到该请求。
- RR5 在 3:0 后继续第四、五图，最终 3:2，没有第六图入口。
- 从比赛房跳转 System，自动带入五图比分、选禁及逐图人员职责；上传六份合成证据并人工校对五图、50 行统计。
- 重复地图统计被自动审查拦截；修正后提交成功且自动审查通过。管理员在工作台审核写入；双方队长各自确认；管理员结算，双方显示 8 / 7 分。
- FD 实际跟随地图、禁用、开赛、暂停、整场结果；人工 CUT 后自动播出停止，直到手动恢复。没有连接真实 OBS。

## 本次发现并修复

1. 第二禁用方默认进入已被规则排除的职责分页：改为默认选择有可禁英雄的分页。
2. 每图重复填写首发：新增“沿用上一图人员与职责”，仍需本图确认。
3. 暂停恢复时双方并发响应冲突：按同一暂停和本队响应版本接纳；旧暂停、旧地图、已变化的本队响应仍被拒绝。
4. 地图结束后的指引误称整场提交，暂停标题仍称赛前：按当前阶段与身份展示。
5. 1280×720 英文界面结算按钮落到页脚，鼠标无法操作：赛果区重新分配高度，压缩矮屏表格间距；鼠标点击和结算已复测成功。
6. RR5 要求管理员重算积分：根据已审核的五图结果预填参赛分加胜场分、计算依据；服务端仍独立校验。
7. System 自动审查拒绝后仍显示“可以提交”：改为“需修正后重试”；前端资料完整只显示“资料已填齐”。

## 验证范围与限制

首发阶段在 1366×768、1920×1080、2560×1440、3840×2160 的 DOM 尺寸检查没有外层横/纵溢出，确认按钮在视口内；390×844 无横向溢出，移动端允许纵向滚动。较矮桌面的赛果结算阶段单独完成鼠标操作复测。2K/4K 的自动截图输出有拼接异常，不能作为完整视觉验收结论。

本机演练中的 System 返回比赛房链接使用测试服务默认的 localhost:5173，部署需使用实际 ACCOUNT_PUBLIC_BASE_URL；正式环境链接须另验。国际化仍存在旧的中英混用和生硬译文，本次没有宣称全语言验收。

FCBT 的自动跟随单元测试与构建完成；浏览器端停在使用条款确认，未代用户接受。真实 OBS、游戏观战视角以及客户端安装包发布不在已完成浏览器证据内。
