# 比赛房选图与 Ban 顺序分离

按用户确认的流程，第二步只选地图与适用的攻防，第三步确认双方首发和职责，第四步先决定 Ban 顺序，再依次禁用英雄。攻击／护送和运载目标显示本队先攻／先防；其他模式不提供攻防选择。地图只读页面展示首攻方，不再混入 Ban 信息。正式房和管理员演练房使用同一套组件和后端规则。

System 增加独立的 `SELECT_BAN_ORDER` 动作与权限检查；攻防保存在 `attackFirstSide`，按真实 A/B 队伍返回。后端先发布，随后发布本前端。旧房间已经确认的 Ban 顺序保留。

验证：
- System 真实隔离数据库开局回归 62/62；演练房 5 项通过，含完整五图。
- 浏览器实际完成选图、双方首发、选择后 Ban、对手先禁用、双方禁用、准备、开赛、第一图结果，以及第二图选地图与先防、刷新核对、重新进入 Ban 顺序。
- 1440×900 和 1280×720 页面无外层滚动；修正 720px 高度下八张地图卡挤占攻防按钮的位置，地图网格内容也不再溢出。
- 390px 中英文无横向溢出，浏览器未记录 JS 错误。
- 房间 UI 回归、四语言词典校验、lint 和生产构建通过。静态预览增加独立 Ban 顺序状态。

所有写入验证使用独立测试数据库和虚拟比赛，未操作正式比赛记录。

补充改动：首图选择权改为赛管直接确认或双方代表共同确认，无须强填理由；有争议时可上传最多 4 张、每张 5 MB 的截图，仅本场赛管和双方代表可读。实际浏览器已验证上传、图片显示、无理由确认及后续选图和临场换位。

战报入口合并为一次点击“上传截图并核对战报”，带入地图、Ban、逐图比分及本图确认的首发与职责。截图数值仍需识别后核对，回放码仍需补充，不自动提交审核或发布赛果。

桌面以宽度及高度共同决定字号、名单列宽、卡片与间距；保留短屏紧凑布局。已检查 1920×1080、2560×1440、3840×2160 的实际选图/首发/Ban 页面，以及含 7 名选手、经理、教练的九人名单。修复名单底部挤出，720p 英雄网格及确认按钮完整显示；390px 无横向溢出。预览新增双方确认状态，并与正式房共用组件。

最终检查：后端真实数据库 65/65，交接及证据读取补充回归通过；前端房间流程、14 项代理测试、四语言、lint 和构建通过。部署前合入主分支新增的队伍报名功能，原工作区未改动。
