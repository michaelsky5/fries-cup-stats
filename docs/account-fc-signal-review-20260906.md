## 页面与行为

- 登录使用全站弹窗，登录后头像菜单提供我的空间、设置和退出。邀请制首发保留受邀邮箱与账号找回入口。
- 账号设置独立于赛季数据加载，按资料、密码、邮箱、设备分区。资料草稿在分区间保留；离开、刷新及主动退出前有草稿保护。
- 我的空间首先展示当前待办和下一场比赛，身份资料保持紧凑。不同身份共用栏目，具体任务注明身份，入口由现有权限控制。
- 首页与任务中心共用赛事待办、周赛参赛准备、比赛与赛果的同步结果；读取失败时显示未同步与重试，不把未知状态显示成零待办。跨赛季、只读、过期版本与无权限状态不会生成可写待办。
- 报名页显示队伍资料、队员确认、提交审核、参赛资格四个步骤；本人确认、队伍关系与正式资格仍按现有业务规则分别处理。
- 周赛队伍页重新组织周期、队伍、周次、核心与名单。常规赛事队伍页、工作人员任务、消息和任务中心同步调整层级、边框、字号与对比度。
- 比赛房使用独立的 FC Signal 样式，移除对旧比赛房样式的运行依赖。赛前集合、地图选择、首发、英雄禁用、比赛进行、地图确认和完整赛果都有可切换的开发预览；保留正式控制器、权限和服务端状态处理。

## 追加升级：参赛准备与待办衔接

首页和任务中心现在使用同一份排序后的待办队列。周赛赛果确认、周期核心、当周参赛确认和名单提交都来自现有 System 接口返回的当前状态。普通赛事任务仍保留原有的业务流程和手动完成机制；不同身份的任务按截止时间与优先级混排。

新增的参赛准备区按队伍、周期与周次展示三个步骤：周期核心、当周参赛、出赛名单。保存草稿、正式提交、管理员锁定分别展示；只读选手能看到队伍进度和负责人提示，不生成代队伍提交的待办。明确不参赛、尚未开放、确认已截止与历史记录各有对应状态。

从待办或准备步骤进入队伍页，会选择对应的周期、队伍和周次，并定位到需要处理的表单。失效链接显示无法访问，不会自动切到另一支队伍。周赛表单新增草稿保护，覆盖切换队伍与周次、离开、刷新和主动退出。提交成功后可直接返回任务中心查看下一步；账号或赛季切换会重新建立工作台及草稿范围。

视觉继续使用 FC Signal 的纸色、细边框、紧凑身份栏与深色任务区域；当前准备步骤用浅黄色提示。任务中心缩减了重复的说明区和空白，将待办与准备进度衔接在同一页。
