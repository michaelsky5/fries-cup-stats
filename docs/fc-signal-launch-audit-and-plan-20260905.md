## 账户业务应怎样验收

当前代码已包含大量业务实现，不能把“尚未真实验证”记成“尚未实现”。本地 `.env.local` 的账户代理指向 `http://127.0.0.1:4500`；本轮读取 `/api/platform/auth/me` 和 `/api/platform/account-launch/seasons/FCR2026` 均得到 502。固定数据的 `/dev/account-preview` 只能验证设计与组件状态。

| 角色/能力 | 必须跑通的业务 | 必须覆盖的失败或限制 |
| --- | --- | --- |
| 访客/账号 | 登录、注册、验证邮箱、退出、过期会话、重置密码、关注迁移 | 接口不可用、错误凭证、未验证账号、登录后返回原目标 |
| 选手 | 身份绑定、赛事申请、邀请接受/拒绝、个人状态、所属队伍和比赛读取 | 无资格、重复申请、窗口关闭、身份冲突、只读赛季 |
| 经理/教练 | 队伍认领、报名、审核申请、邀请成员、阵容提交/锁定、经理/教练关系维护 | 名额与资格限制、审核拒绝、撤回、权限改变、归档锁定 |
| 比赛双方 | 从任务进入房间，签到、首发、选禁、报分、对方确认 | 超时、断线、重复提交、并发更改、弃权、争议、结果未确认 |
| 裁判/赛管 | 职责任务、比赛处理、争议处理、结果完成后的回写 | 非指派访问、状态已变化、重复结算、归档限制 |
| 解说 | 可用时间、排班确认、赛前资料和比赛入口 | 冲突时段、撤回/变更、权限和发布状态 |
| 通知/沟通/预测/周赛 | 从入口打开、读写限制、提交、刷新后保留结果，关联任务同步 | HIDDEN/READ_ONLY/WRITE、重试、过期状态、未开放赛季 |
| 账号安全/邀请激活 | 密码和会话、有效邀请、接受后身份及工作台一致 | 缺失/过期/使用过的邀请、错误受邀账号、重复接受 |

先准备专门的测试赛事、各角色测试用户和可重置数据。按现有后端规则执行；如前后端在签到、确认、争议或特殊赛果规则上不一致，先列出具体冲突再请主办方决定。本轮不制定新的赛事规则。

5. 键盘、可见焦点、弹窗关闭/返回焦点、空结果与错误恢复可用；必要动效尊重减少动态设置。
6. 实际图片加载成功；涉及导出的页面必须检查生成后的 PNG/PDF，而不只看弹窗。
7. 有意义的选择器/数据契约测试、相关 lint、构建通过；将浏览器和真实业务验收结果单独记录。
8. 验收后才把该批记为完成。账户预览、模拟数据测试、构建成功不能代替实际角色和服务端持久化验证。
